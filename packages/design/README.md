# @mcpproxy/design

Визуальный язык проекта. Используется всеми пакетами — Electron, деки презентаций,
отчёты bench.

## Установка в пакете

```json
{ "dependencies": { "@mcpproxy/design": "workspace:*" } }
```

```ts
import { palette, dark, riskRole, stageLabel } from '@mcpproxy/design';
```

```css
@import '@mcpproxy/design/css';   /* reset + tokens + base */
```

## Источник истины

`src/tokens.ts` и `src/palette.ts` — единственный источник значений.
`dist/css/tokens.css` **генерируется** из них при `yarn build`.
Править CSS руками нельзя: правка молча разъедется с TS и всплывёт через месяц
в виде «в Electron кнопка другого оттенка, чем на слайде».

## Палитра

Построена вокруг фирменного красного Opera — **`#FF1B2D`** (`--op-red-500`).
Нейтральные слегка холодные, без чистого чёрного — как поверхности Opera One.

## Главное правило: красный — семантика, а не украшение

В приложении для наблюдения за безопасностью красный обязан что-то значить.
Если красить им кнопку «Сохранить», он перестанет читаться как сигнал, и настоящая
критическая строка в таймлайне потеряется среди декора.

Opera Red появляется ровно в трёх местах:

1. знак продукта — лого, активный индикатор навигации;
2. кольцо фокуса;
3. критические состояния — атака прошла, цепочка аудита сломана, сработал mandatory deny.

**Основное действие красится инверсным нейтральным** (`.btn-primary`), а не брендовым
красным. Красный получает только `.btn-danger`.

## Четыре роли, а не три

Приложение существует, чтобы человек за долю секунды отличал «защита сработала»
от «защита не сработала». Красить оба исхода красным — значит потерять смысл продукта.

| Роль | Цвет | Значение | Пример |
|---|---|---|---|
| `ok` | зелёный | прошло штатно | тесты выполнены, вызов разрешён |
| `warn` | **янтарный** | **отбито — защита сработала** | `network denied: evil.io`, отказ валидатора |
| `danger` | красный | **плохо по-настоящему** | атака прошла в baseline, цепочка разошлась, mandatory deny |
| `info` | синий | ждём человека | апрув в очереди, элицитация |
| `human` | фиолетовый | решение человека действует | одобрено вручную, активен TTL |

Янтарь и красный различаются принципиально. «Песочница отбила попытку выхода в сеть» —
это янтарь: система работает как задумано. Красный означает, что что-то пошло не так.

Исключение: `mandatory-deny` красится красным, хотя попытка отбита. Отбито успешно,
но сам факт попытки записи в `.git/hooks` означает, что запущенный код пытался
закрепиться в системе. Это не рутина.

## Семантика домена

`src/semantic.ts` маппит состояния прокси в роли — компоненты спрашивают роль,
а не цвет, поэтому смена палитры не требует правок в компонентах.

- `verdictRole` — вердикт вызова (`allowed` / `denied` / `pending_approval` / `error`)
- `stageLabel`, `stageOrder` — 13 стадий вызова из `docs/07-contracts.md`
- `riskRole`, `riskLabel` — тиры риска
- `sandboxRole`, `sandboxLabel` — режимы песочницы
- `violationRole`, `violationLabel` — типы нарушений песочницы
- `annotationRole` — бейджи MCP tool annotations, роль зависит от значения

## Правила, зашитые в базовые стили

- **Цвет никогда не единственный носитель смысла.** Рядом с ним всегда текст или символ —
  дальтонизм и проектор на демо ломают чистую цветовую кодировку.
- **Моноширинный для argv, путей и хэшей.** Не украшение: пользователь глазами сверяет
  аргументы, а пропорциональный шрифт скрывает разницу между `--flag` и `--flаg`
  с кириллической «а». Перенос по словам в argv запрещён — разорванный аргумент
  читается как два разных.
- **Кольцо фокуса не убирается.** Клавиатурная навигация — основной способ работы
  с длинным таймлайном.
- **`sandbox: none` красится опасным всегда**, включая баннер `.unsandboxed-banner`.
  Baseline-режим не должен ни секунды выглядеть как обычная работа.

## Темы

Тёмная — основная: приложение живёт рядом с терминалом и смотрит на него часами.
Светлая равноправна, но проектируется второй.

Три состояния: явный выбор (`[data-theme]`) побеждает всегда, системная настройка
по умолчанию даёт тёмную.
