### Major — сырая строка `pattern` всё-таки пересекает границу пакета

`packages/contracts/src/tool.ts:98`
(плюс `packages/contracts/src/types.ts:31-37`, `packages/contracts/src/validate/regex.ts:14-16`,
`docs/10-honest-limitations.md` раздел «ReDoS: чего стоил замер», spec R29)

Заявление записано в трёх местах одинаково: «через границу пакета едет **скомпилированный
матчер**, а не строка `pattern`… получив строку, потребитель вправе вызвать
`new RegExp(pattern)` и вернуть ровно тот вектор, который закрыт на загрузке. У матчера
наружу не выставлены ни `source`, ни `flags`».

Строка выезжает наружу двумя путями, и оба — в этом же диффе:

1. `parseManifest` возвращает `{ ok: true, manifest, matchers }`
   (`src/validate/index.ts:76`). `StringParam.pattern` объявлен **обязательным**
   (`src/manifest.generated.ts:94`, `schema/mcpproxy.schema.json:84`), то есть
   `manifest.tools[r].params[p].pattern` — та самая голая строка, лежащая рядом с матчером.
2. `toTool` копирует её дословно в `inputSchema.properties[p].pattern`
   (`src/tool.ts:98`) — то есть в payload, который уезжает модели через `tools/list` и
   компилируется бэктрекящим движком клиента. Тест это фиксирует как желаемое
   (`src/tool.test.ts:88`).

Конкретность: `src/validate/parse.test.ts` (кейс «не бэктрекит на вложенном
квантификаторе») доказывает, что `^(a+)+$` — **законный** паттерн манифеста: RE2 проходит
его за 0.009 мс и `parseManifest` возвращает `ok: true`. Этот же паттерн затем уезжает
строкой в `Tool.inputSchema` и в `Manifest`. `regex.test.ts` («не выставляет наружу source и
flags») проверяет только форму объекта-матчера и потому зелёный.

Fix (поверхность заморожена, поэтому реалистичен второй вариант):
— либо убрать `pattern` из проекции `toTool` и не отдавать `manifest` целиком, оставив
`matchers` единственным каналом (ломает форму `ParseManifestResult` и `Tool` — до заморозки
это ещё возможно, после нет);
— либо честно переписать абзац в `10-honest-limitations.md` и комментарии
`types.ts:31-37` / `regex.ts:14-16`: RE2 закрывает ReDoS **внутри демона на загрузке**, а
паттерн виден потребителю и через `Manifest`, и через `Tool`, и гарантия на клиента MCP не
распространяется. Сейчас документ, который существует ради честности границ, границу
переоценивает.

### Major — `asRecipeName` слабее, чем `propertyNames` схемы, и `constructor` проходит

`packages/contracts/src/ipc.ts:21-26`

```ts
export const RECIPE_NAME_PATTERN = /^[a-z][a-z0-9_]{0,63}$/;
export function asRecipeName(value: string): RecipeName {
  if (!RECIPE_NAME_PATTERN.test(value)) throw new TypeError(`не имя рецепта: ${value}`);
```

Схема ограничивает имя **двумя** условиями (`schema/mcpproxy.schema.json:18-21`):

```json
"propertyNames": { "pattern": "^[a-z][a-z0-9_]{0,63}$",
                   "not": { "enum": ["constructor", "prototype", "__proto__"] } }
```

`docs/07-contracts.md` прямо объясняет, зачем вторая половина: «Одного паттерна мало:
`constructor` ему соответствует». Тот же вывод записан в handoff-notes п.1 и в spec R32.
Ветка IPC взяла только первую половину: `asRecipeName('constructor')` возвращает
`'constructor' as RecipeName`.

Почему это не косметика. `asRecipeName` — единственный рантайм-страж имени на границе
сокета (И5). Демон дальше делает `manifest.tools[recipeName]`; `manifest.tools` — обычный
объект из `doc.toJS()`, поэтому `tools['constructor']` резолвится по цепочке прототипов в
`Object` — истинное значение, не являющееся `Recipe`. Проверка вида
`const recipe = tools[name]; if (!recipe) deny;` её пропустит. Схема этот вход закрывает,
брендированный конструктор — нет.

Комментарий `ipc.ts:18-20` при этом утверждает: «Та же форма, что у `propertyNames` схемы
манифеста… Совпадение двух копий проверяет тест — иначе они разъедутся». Копии уже
разъехались, а тест (`src/tool.test.ts:108-114`) сравнивает только
`RECIPE_NAME_PATTERN.source` с `propertyNames.pattern` и половину `not/enum` не смотрит
вовсе. Заголовок соседнего кейса — «asRecipeName отвергает то, что отвергает схема»
(`tool.test.ts:116`) — для `constructor` ложен.

Fix: в `asRecipeName` добавить тот же явный отказ трём именам и расширить тест парности до
обеих половин `propertyNames` (сравнивать и `pattern`, и `not.enum`), а не только `source`.

`packages/contracts/src/validate/refine.ts:135`

Практическая опасность невелика (`{}` в пути — просто каталог с таким именем, пока подстановку
делает только E2 и только в argv), но заявленный инвариант шире кода.

### Minor — `..`-проверка root даёт ложное срабатывание на каталоге вида `..name`

`packages/contracts/src/validate/refine.ts:119-120`

```ts
const outside = relative(manifestDir, resolved);
if (outside.startsWith('..')) report(path, 'относительный root не может выходить за каталог манифеста');
```

Классический промах: `root: "./..cache"` резолвится в `<manifestDir>/..cache`,
`relative` возвращает `'..cache'`, `startsWith('..')` истинно — и легитимный **подкаталог**
объявляется выходом за пределы. Настоящий выход (`'../x'`, `'..'`) при этом ловится верно,
то есть дефект односторонний: ложный отказ, не ложное разрешение.

Fix: `if (outside === '..' || outside.startsWith(`..${sep}`))` с `sep` из `node:path`.

### Minor — санитайзер склеивает слова на табуляции, ровно как обещал не делать

`packages/contracts/src/tool.ts:83-84`

```ts
// Переводы строки схлопываются ДО вырезания невидимых: иначе `a\nb` склеилось бы в `ab`.
const flattened = withoutAnsi.replace(/[\r\n]+/g, ' ');
const visible = flattened.replace(INVISIBLE, count);   // INVISIBLE = /[\p{Cc}\p{Cf}]/gu
```

В `\p{Cc}` входят не только `\r\n`, но и `\t` (U+0009), `\v` (U+000B), `\f` (U+000C).
Схлопывается только первая пара, остальные три просто удаляются, поэтому
`"колонка\tзначение"` → `"колонказначение"` — тот самый дефект, ради предотвращения которого
комментарий строкой выше и объясняет порядок операций. Комментарий описывает намерение,
которого код не выполняет для трёх символов из четырёх.

Fix: `replace(/[\r\n\t\v\f]+/g, ' ')` (или `/\s+/gu`, раз следующим шагом всё равно идёт
схлопывание двойных пробелов).

### Minor — шесть кейсов заглушек проходят вхолостую при провале разбора

### Nit — недостижимая ветка `?? 1` в `durationToMs`

`packages/contracts/src/lock.ts:23`

```ts
return Number(match[1]) * (UNIT_MS[match[2] as string] ?? 1);
```

Регулярка строкой выше уже сузила `match[2]` до `ms|s|m|h`, и все четыре — ключи `UNIT_MS`.
Ветка `?? 1` недостижима; при этом её семантика («неизвестная единица = миллисекунды»)
противоположна духу функции, которая на строку выше бросает на любой неразобранной строке.

Fix: `const unit = UNIT_MS[match[2]!]; if (unit === undefined) throw new TypeError(...)`.

### Nit — нормализация дедуплицирует `deny` непоследовательно

### Nit — `slice` по кодовым единицам режет суррогатную пару

`packages/contracts/src/tool.ts:87`

### Major — `Diagnostic.message` санитизируется у одного производителя из пяти, а обещание записано абсолютное

Утверждение добавлено этой же дельтой в двух местах:

- `packages/contracts/src/types.ts:54-58` — «Безопасен для отрисовки: **всё**, что
  интерполируется сюда из недоверенного манифеста, проходит через `sanitizeDescription`»;
- `docs/07-contracts.md:399-401` — то же дословно.

Санитизирован ровно один путь — причина RE2 (`src/validate/index.ts:56`). Остальные четыре
интерполируют недоверенный текст сырьём, и **два из них добавлены этим же коммитом**:

1. `packages/contracts/src/validate/refine.ts:112` (НОВОЕ) —
   `` `…нет в defaults.env.allow: ${name}` ``. `name` — элемент рецептного `env.allow`, а в
   схеме это `{"type": "string"}` без `SafeText` и без `pattern`
   (`schema/mcpproxy.schema.json`, `$defs.EnvPolicy.allow.items`), то есть произвольные
   байты из манифеста. Это ровно тот брат, ради которого фикс с RE2 и делался.
2. `packages/contracts/src/validate/lock.ts:68` (НОВОЕ) — `` `lock не разобран как JSON:
   ${error.message}` ``. V8 вкладывает в это сообщение **фрагмент самого файла**. Замер:
   `JSON.parse('{ "a": <ESC>[31mBADTOKENHERE }')` даёт
   `Unexpected token '<ESC>', "{ \"a\": <ESC>[31mBADTO"... is not valid JSON`. Подменённый
   lock — это буквально сценарий, ради которого парсер и написан.
3. `packages/contracts/src/validate/lock.ts:76` (НОВОЕ) —
   `` `версия lock ${String(data.version)}` ``: `data.version` — произвольное значение JSON,
   `String()` строку отдаёт как есть.
4. `packages/contracts/src/validate/yaml.ts:41,53,62` — `${error.message}` / `${warning.message}`
   от `yaml@2.9.0`. Это худший случай: библиотека вкладывает в текст **дословную выдержку из
   исходника с переводами строк и кареткой**. Замер на этом дереве, вход

   ```
   MISSING_CHAR: Tags and anchors must be separated from the next token by white space
   at line 2, column 13:

   foo: !custom<ESC>[31mtag v
               ^
   ```

подписано в замороженном `.d.ts`, и потребитель, прочитав его, отрисует `message` как есть.

ограничено, — а не тот, где эхо это целая строка исходника.

**Fix.** Прямая подстановка `sanitizeDescription` в `yaml.ts` не годится: она схлопывает
`\n`, а именно перевод строки делает выдержку с кареткой читаемой. Либо
(а) обрезать выдержку до первой строки (`error.message.split('\n')[0]`) и санитизировать её,
либо (б) завести в `tool.ts` вариант санитайзера, сохраняющий `\n`, и применить его во всех
четырёх местах, либо (в) сузить оба утверждения до правды: «через `sanitizeDescription`
проходит причина RE2; остальной `message` может нести текст манифеста, отрисовывать
защитно». Вариант (в) стоит одну строку и не двигает поверхность, но тогда `docs/07-contracts.md`
теряет ровно то утверждение, ради которого абзац и написан.

### Minor — санитайзер по-прежнему склеивает слова на U+0085 (NEL)

`packages/contracts/src/tool.ts:81-85`

Комментарий, добавленный дельтой: «Здесь именно **все пятеро**, а не `\r\n`: `\t`, `\v` и `\f`
тоже входят в `\p{Cc}`, то есть без них три символа из пяти просто удалялись бы —
`"колонка\tзначение"` → `"колонказначение"`, ровно тот дефект…».

В `\p{Cc}` 65 символов, а не пять. Среди них U+0085 NEL — настоящий разделитель строк

некоторых редакторов. Замер (тот же конвейер, что в функции): `a<U+0085>b` → `ab`, то есть
дефект, объявленный комментарием закрытым, воспроизводится один в один на другом символе.

Fix: `/[\r\n\t\v\f\u0085]+/g` (или `/[\p{Zs}\r\n\t\v\f\u0085]+/gu`, раз следующим шагом всё
равно идёт схлопывание двойных пробелов) и поправить «все пятеро» на «разделители строк и
табуляции из `\p{Cc}`».

   `Diagnostic` во всём `packages/*/src` ровно три: `locate.ts:57`, `validate/lock.ts:50`,
   `validate/yaml.ts:18`; первые два санитизируют оба поля, третий кладёт `pointer: ''`
   (уровень документа, сырому тексту взяться неоткуда). Непокрытых нет.
2. **Предел теперь по значению и стоит везде, где встречается длительность.** `$ref` на
   `#/$defs/Duration` в схеме ровно два — `schema/mcpproxy.schema.json:32` (`defaults.timeout`)
   и `:64` (`Recipe.timeout`); `refine.ts:233` и `refine.ts:244` закрывают оба. Замер:
   `999999999h` → `invariant@defaults.timeout: … 3599999996400000 мс при 2147483647`,
   рецептная — то же по `tools.x.timeout`, `2147483s` → `ok`, `2147484s` → отказ.
   `durationToMs` на этом пути получает только строку, уже принятую ajv (ранний `return`
   в `index.ts:98-101`), и паттерн схемы `^[0-9]{1,9}(ms|s|m|h)$` — строгое подмножество
   `^([0-9]+)(ms|s|m|h)$` из `lock.ts:37`, поэтому **сегодня** бросок недостижим. Но именно
   на этой связке — находка F-1.
3. **`notHashable` покрытие не потерял — проверено перебором, а не рассуждением.** Каждая
   строка `NormalizedManifest` — дословная копия строки или **ключа** сырого манифеста
   (`lock.ts:207-238`), а `canonicalizeJcs` проверяет well-formed и у ключей тоже
   (`jcs.ts:93`), поэтому вектор «одиночный суррогат в имени рецепта/параметра» (в сыром
   дереве — ключ, в нормализованном — значение) закрыт с обеих сторон. Вычисляемых чисел
   два: `timeoutMs` — ограничен `checkDuration`, `maxBytes ?? 65536` — литерал. Нормализованная
   форма на два уровня **глубже** сырой (`tools[] → own → params[] → schema`), но обе ≈9 при
   `JCS_MAX_DEPTH = 128`, а вложенность манифеста ограничена схемой структурно. Замер: десять
   векторов (суррогат в `description`, `exec`, `env.allow`, `sandbox.deny`, значении `enum`,
   имени рецепта, имени параметра; `maxBytes: 1e999` в `defaults` и в рецепте; `999999999h`)
   — **ни одного случая «сырой канонизируется, нормализованный нет»**: каждый отвергается
   до загрузки, шестью схемными и четырьмя `invariant`. Тестовое покрытие `notHashable`
   вернулось: `refine.test.ts:186` и `:194` — два кейса с суррогатом (`description` и строка
   песочницы `defaults`).
4. **Пустой `pointer` — защитимо, оставить можно; аналогия при этом не полная.** У
   `size-limit` и `yaml` пути нет физически (документ не разобран); здесь документ разобран,
   и путь в принципе вычислим — довод «у документного отказа нет пути» держится по *коду*
   диагностики, но не по *доступности* атрибуции. Цена для потребителя ненулевая и ровно
   одна: на манифесте в 258 КБ человек получает «манифест не хэшируется … одиночный суррогат
   в позиции 1», где `1` — смещение внутри виноватой строки, а не в документе, и ни `pointer`,
   ни `line`/`column` (обе `1`) не говорят, в каком из сотен рецептов искать. Это
   диагностируемость, не корректность, и регресса нет: до коммита `pointer` был так же пуст.
   Дешёвое улучшение, если захочется: на **пути отказа** (он терминальный, цена не в горячем
   пути) прогнать `canonicalizeJcs` по слотам — `defaults`, затем каждый `tools[name]` — и
   отдать `pointer: 'tools.<имя>'` первого упавшего. Ниже порога, отдельной находкой не считаю.
5. **Доки правдивы, противоречий внутри `docs/` не внесено — кроме расхождения с замороженным

   перечисляет ровно то, что производят `refine` и `notHashable`; абзац про хэшируемость

   `locate.ts:52-58` и подтверждён замером. Мест в `docs/`, объявляющих `999999999h` или
   `3600000h` законными, нет; фикстуры `packages/contracts/recipes/mcpproxy.yaml:9,51,73`
   и примеры документа (`120s`, `300s`, `600s`) новой проверкой не задеваются.
6. **Снапшот отличается только законным.** `git show bcf50c8 -- packages/contracts/api-surface.snapshot.txt`

### Находки

- **F-1 (55). Коммит снял единственную страховку от броска `durationToMs` внутри
  `parseManifest` и тем же дифом добавил нового голого вызывающего; инвариант «не бросает»
  держится теперь только на нигде не запиннённом совпадении двух регулярок.**
  До коммита каждый вызов `durationToMs` на пути разбора был внутри `try/catch` функции
  `notHashable` (через `normalizeManifest`), и `validate/index.ts` это прямо декларировал
  строкой, которую этот же диф удалил: «*Побочно она страхует и `normalizeManifest`:
  `durationToMs` бросает на неизвестной единице*». Теперь `refine.ts:162` зовёт
  `durationToMs(value)` голым, а `notHashable` (`index.ts:96`) канонизирует сырой манифест и
  `normalizeManifest` больше не трогает — сетки нет ни у нового вызывающего, ни у старого.
  `refine` вызывается из `parseManifest` **вне** `try/catch` (`index.ts:105`), а контракт
  (`docs/07-contracts.md:383`) обещает: «`parseManifest` возвращает размеченный результат,
  **а не бросает**». Обещание держится ровно на одном необъявленном факте: паттерн
  `schema/mcpproxy.schema.json:208` (`^[0-9]{1,9}(ms|s|m|h)$`) — подмножество регулярки
  `src/lock.ts:37` (`^([0-9]+)(ms|s|m|h)$`). Связка не проверяется ничем: `schema.test.ts:58`
  пиннит только длину (9 против 10 цифр и только на единице `s`), `lock.test.ts:60-65` —
  только сам `durationToMs` на четырёх литералах. Добавление в схему единицы `d` (а этот же
  коммит мотивирует его сюжетом «манифест просит почти никогда не прерывать») превращает
  диагностику в необработанный `TypeError` из публичной точки входа — ровно тот класс отказа,
  ради устранения которого написаны `parseLockFile` и `notHashable`.
  *Фикс (любой из двух, оба однострочные).* Либо не звать бросающую функцию вслепую —
  `refine.ts:162`: `const match = /^([0-9]+)(ms|s|m|h)$/.exec(value); if (match === null) return;`
  (форму уже отверг ajv, дублировать диагностику незачем). Либо запиннить связку тестом рядом
  со `schema.test.ts:58`: вытащить единицы из паттерна схемы и на каждой потребовать
  `expect(() => durationToMs('1' + unit)).not.toThrow()` плюс утверждение, что набор единиц
  в паттерне совпадает с ключами `UNIT_MS`. Второе предпочтительнее: оно закрывает и
  `normalizeDefaults` (`lock.ts:179`) с `normalizeRecipe` (`lock.ts:222`), которые зовут
  `durationToMs` так же голо.
- **F-2 (52). Замороженный тип не несёт гарантии, которую документ уже объявил, а снапшот
  публичной поверхности переснят в этом же коммите — с прежним текстом.**
  `docs/07-contracts.md:413` теперь утверждает «`message` **и `pointer`** безопасны для
  отрисовки», а `packages/contracts/src/types.ts:51-52` описывает `pointer` как «Точечный путь
  внутрь документа, например `tools.publish_release.params.tag`» — ни слова о санитизации,
  тогда как у соседнего `message` (`types.ts:61-67`) гарантия расписана прямо в типе, и код
  на это опирается («*`Diagnostic.message` объявлен безопасным для отрисовки в замороженном
  типе*», `locate.ts:39-40`). В этом проекте контракт — замороженный тип и снятый с него
  `api-surface.snapshot.txt`; снапшот здесь перегенерирован и по-прежнему показывает `pointer`
  без гарантии. Два следствия. Первое: следующий мейнтейнер, читая поверхность, вправе счесть
  `sanitizeDescription` в `locate.ts:58` и `validate/lock.ts:61` косметикой и снять её.
  Второе, содержательное: санитизация делает `pointer` **лоссовым** — замер даёт `tools.ab`
  для ключа `a<ESC>[31m<BIDI>b`, — то есть поле перестало быть путём, который резолвится в
  документе (`doc.getIn(pointer.split('.'))`), а тип и документ (`07-contracts.md:384-385`)
  продолжают описывать его именно как путь. Навигация не ломается только потому, что реальные
  координаты едут в `line`/`column`, и это тоже нигде не сказано.
  *Фикс:* в `types.ts:51` заменить однострочный док на «Точечный путь внутрь документа,
  например `tools.publish_release.params.tag`. Безопасен для отрисовки наравне с `message`:
  санитизируется в конструкторах диагностики, поэтому сегмент, пришедший из недоверенного
  ключа, может отличаться от буквального ключа документа — точная позиция всегда в
  `line`/`column`». Затем `node scripts/update-api-surface.mjs`; `api-surface.test.ts` иначе
  покраснеет — это и есть гейт.
