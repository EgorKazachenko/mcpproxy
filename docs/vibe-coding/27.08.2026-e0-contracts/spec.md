# E0 — заморозка `packages/contracts`

**Ветка:** `v2/e0-contracts` · **Трек:** full · **Источник истины:** `docs/07-contracts.md`,
уточнённый разведкой 2026-08-27 (см. «Что разведка изменила»).

## Цель

Заморозить контракт, от которого зависят семь эпиков: схема манифеста, схема события
аудита, аннотации MCP и вывод риск-тира, lock-файл, IPC. После заморозки `contracts`
меняется только явным решением владельца.

## Границы

**В объёме:** `packages/contracts` целиком, тест-инфраструктура воркспейса, правки
`packages/design` там, где расширение юнионов ломает компиляцию, и правки `docs/`,
где разведка опровергла написанное.

**Вне объёма:** реализация политики (E1), валидатора argv (E2), песочницы (E3),
MCP-поверхности (E4), аудит-райтера (E6). Контракт объявляет форму — не поведение.

## Решения владельца (приняты 2026-08-27)

| # | Решение | Выбор |
|---|---|---|
| D1 | Ревизия MCP | `2025-11-25` — то, что объявляет released SDK `1.30.0` |
| D2 | Формат события | Свой внутренний шейп + экспортёр `toOtlp()` |
| D3 | ReDoS | `re2`, синтаксис RE2 объявлен частью контракта |
| D4 | Хэш-цепочка | Всё событие, RFC 8785 JCS, минус `chain.self` |

## Требования

### Манифест

**R1.** `packages/contracts` публикует `schema/mcpproxy.schema.json` — JSON Schema
2020-12 с `$id`, валидную по мета-схеме. Схема — написанный руками артефакт, а не
побочный продукт: её читают редактор, документация и демон.

**R2.** Схема кодирует инварианты `07-contracts.md` структурно, а не комментарием:
`string` обязан иметь `pattern`; `path` обязан иметь `root`; `enum` обязан иметь
непустой `values`; `additionalProperties: false` на каждом объекте; союз параметров —
`oneOf` из `$ref` на самодостаточные ветки с `const`-дискриминатором `type`.

**R3.** TS-типы генерируются из схемы в сборке и экспортируются как простые
интерфейсы. `.d.ts` пакета не ссылается ни на одну внешнюю библиотеку — потребитель,
не установивший валидатор, компилируется.

**R4.** Единственная публичная точка загрузки — `parseManifest(yamlText, opts)`,
возвращающая размеченный результат: либо манифест, либо список диагностик с
`файл:строка:колонка` и точечным путём (`tools.run_tests.params.pattern`).
Скомпилированный валидатор ajv наружу не экспортируется.

**R5.** `parseManifest` выполняет проверки, которые JSON Schema выразить не может, и
ни одна из них не может быть пропущена вызывающим: `root` абсолютен либо разрешается
относительно манифеста; `pattern` компилируется через RE2; `exec[0]` не содержит
метасимволов оболочки; `argv`-элемент содержит `{}` не более одного раза; ни один
параметр не подставляется в `exec[0]`, `cwd` или профиль песочницы.

**R6.** Каждая ветка `$defs` схемы имеет запись в таблице проверок R5 либо явную
пометку «проверок не требуется». Тест падает, если ветка добавлена без записи.

**R7.** Регулярные выражения манифеста — синтаксис RE2. Компиляция через `re2`;
паттерн, который RE2 не принимает, — ошибка загрузки с указанием причины.
Тот же движок передаётся в ajv через `code.regExp`.

**R8.** Разбор YAML отбивает враждебный манифест: лимит размера файла до разбора,
неизвестный тег — отказ, дубли ключей — отказ, превышение числа алиасов — отказ.

### Риск и аннотации

**R9.** Контракт объявляет четыре аннотации MCP с дефолтами спеки: `readOnlyHint`
`false`, `destructiveHint` `true`, `idempotentHint` `false`, `openWorldHint` `true`.

**R10.** `deriveRiskTier(annotations)` — чистая функция без ввода-вывода, реализующая
таблицу тиров и учитывающая оговорку спеки: `destructiveHint` и `idempotentHint`
значимы только при `readOnlyHint === false`. Отсутствие аннотаций даёт `high`.

**R11.** Граница гарантии записана в контракте: молчание манифеста может сделать
рецепт только опаснее, но явный `readOnlyHint: true` понижает тир, и спека требует
считать аннотации недоверенными. Формулировка «fail-safe by construction» заменяется
на эту, более узкую.

### Событие аудита

**R12.** Контракт объявляет тип события со всеми полями `07-contracts.md` и
перечислением 13 стадий, уже живущим в `domain.ts`. Внутренний шейп — вложенный,
время — ISO-8601, enum'ы — строки.

**R13.** `toOtlp(event)` отображает событие в валидный OTLP/JSON: `traceId`/`spanId`
в hex-строках, числовой `kind`, `startTimeUnixNano`/`endTimeUnixNano` десятичными
строками, атрибуты `gen_ai.*` и `mcp.*` под именами, подтверждёнными разведкой.

**R14.** Тест запрещает snake_case-ключи в выводе `toOtlp` и падает при их появлении.
Приёмник OTLP обязан молча игнорировать неизвестные поля, поэтому такая ошибка иначе
не обнаруживается вообще.

**R15.** `chainHash(event, prevHash)` считает `chain.self` по RFC 8785 JCS от всего
события без поля `chain.self`. `verifyChain(events)` возвращает индекс первой
разошедшейся записи.

### Lock, IPC, поверхность

**R16.** Контракт объявляет схему `mcpproxy.lock` и функцию нормализованного
представления рецепта, по которому считается хэш. Представление пригодно для диффа
«было / стало» целиком, без усечения.

**R17.** Контракт объявляет форму IPC-запроса `{recipe, params, sessionId}` и делает
невыразимой передачу argv, пути к бинарю, `cwd` или профиля песочницы.

**R18.** Контракт объявляет проекцию рецепта в `Tool` ревизии `2025-11-25` с полями
`resultType`, `ttlMs`, `cacheScope` как опциональными, чтобы переход на `2026-07-28`
не потребовал изменения замороженного контракта.

**R19.** `sanitizeDescription` — чистая функция, применяемая при генерации
`tools/list`. Манифест недоверенный, а описания идут прямо в контекст модели.

**R20.** Репозиторий содержит четыре рецепта-заглушки, валидных по схеме:
`run_tests`, `build_project`, `analyze_logs`, `publish_release`. Последний —
единственный high-risk, он нужен сценарию S8.

### Инфраструктура и заморозка

**R21.** В воркспейсе появляется работающий тест-раннер (vitest). `yarn test`
запускает тесты и падает, когда они красные. Сегодня он выходит с нулём, не запустив
ничего, — то есть гейт `build-test` зелёный на пустоте.

**R22.** `yarn typecheck && yarn build && yarn test` зелёные на всём графе пакетов,
включая `design`, чьи десять исчерпывающих `Record<Union, …>` ломаются при любом
расширении юнионов контракта.

**R23.** Заморозка зафиксирована: `CONTRACTS_VERSION`, запись в `docs/`, что
`contracts` меняется только явным решением, и удаление `TODO(E0)` из `index.ts`.

### Правки документации

**R24.** Исправлены утверждения, опровергнутые разведкой: направление переезда OTel
(конвенции MCP пришли в core в v1.42.0 — они оттуда **ушли**); несуществующие
`mcp.tool.name`, `mcp.request.id`, `mcp.transport`; переехавшие URL спеки MCP;
атрибуция «tool poisoning» / «line jumping» на Invariant Labs, а не на спеку.

**R25.** В `10-honest-limitations.md` добавлен ReDoS через `pattern` манифеста —
вектор, которого в документе нет, и то, чем он закрыт.

### Найдено ревью плана (раунд 1)

**R26.** Контракт объявляет форму подтверждения целиком: `ApprovalChannel`
(`electron` | `elicitation`), `ApprovalDecision`, `ApprovalScope`
(`once` | `until` | `recipe_and_args`), `expiresAt` — **абсолютное** ISO-время, а не
относительный TTL, и `argsHash`. Плюс формы `ApprovalRequest` и `ApprovalVerdict` с
непрозрачным идентификатором запроса, чтобы вердикт из рендерера нельзя было отнести
к другому ожидающему вызову. Без этого S8, атака A14 и ASI09 не реализуемы, а
дорисовывать это после заморозки — ломать контракт для E5 и E7.

**R27.** Lock покрывает манифест целиком, а не только рецепты по отдельности:
`manifestHash`, нормализация уровня `defaults` (потому что эффективный профиль
песочницы и env-allowlist рецепта — это `defaults`, слитый с блоком рецепта),
и `diffLock`, возвращающий `added` / `removed` / `changed`. Добавленный и удалённый
рецепт обязаны обнаруживаться, а не только изменённый. Порядок параметров входит в
нормализованное представление, потому что от него зависит собранный argv.

**R28.** Lock хранит одобренное нормализованное представление рецепта, а не только его
хэш. SHA-256 необратим, поэтому из одного хэша невозможно построить сторону «было» для
диффа, которого требуют S7 и ADR-0006 — целиком и без усечения.

**R29.** Скомпилированный матчер пересекает границу пакета вместо голой строки
`pattern`. Иначе E2 волен вызвать `new RegExp(pattern)` и вернуть ReDoS, который R7
закрыл только на загрузке.

**R30.** Событие несёт монотонную длительность стадии в микросекундах рядом с
ISO-временем стены. Оверхед, который публикуют S2 и `09-metrics-and-eval.md` (p50 9 мс
при цели ≤50 мс p95), не выводится из меток, квантованных до миллисекунды.

**R31.** У заморозки есть исполняемая проверка: снапшот публичной поверхности `.d.ts`
всех трёх входов, падающий в CI при любом изменении; `version: {const: 1}` в схеме;
записанное правило, когда двигается `CONTRACTS_VERSION`.

**R32.** Ключи `tools` и `params` ограничены `propertyNames`, поэтому `__proto__` и
`constructor` — ошибка загрузки, а не имя рецепта.

## Чек-лист приватности

| Вопрос | Ответ |
|---|---|
| Собираем ли новые персональные данные | Нет. Контракт объявляет форму, ничего не пишет |
| Что чувствительного описывает событие | `argv`, `cwd`, имена разрешённых переменных окружения, домены. Значения переменных — никогда |
| Уходит ли что-то наружу | Нет. `toOtlp` — чистая функция; экспорт запускает человек |
| Логируются ли секреты | Нет. Env-allowlist на входе, редакция вывода — E6 |
| Есть ли пути пользователя в артефактах | `cwd` и резолвнутые пути — да, локально. В тестах — только временные каталоги |

## Критерий готовности

Все `R1..R25` реализованы; `yarn typecheck && yarn build && yarn test` зелёные;
четыре заглушки грузятся через `parseManifest` без диагностик; схема валидна по
мета-схеме 2020-12; цепочка на синтетическом логе верифицируется, а правка одного
байта в середине даёт индекс расхождения.
