# E2 — валидатор параметров, резолв путей, сборка argv

**Ветка:** `v2/e2-validate` · **Трек:** full · **Источник истины:** `docs/06-epics.md` (строка E2),
`docs/07-contracts.md`, инварианты И1–И3 и И5 из `docs/02-architecture.md`, замороженная
поверхность `packages/contracts`.

## Цель

Первая линия обороны: превратить недоверенный `{recipeName, params}` в проверенный argv-массив,
резолвнутые пути и отказ с внятной причиной — так, чтобы строки команды не существовало ни на
одном шаге. Всё, что E2 отдаёт наружу, потребляет E3 (запуск) и E4 (шов).

## Границы

**В объёме:** `packages/core/src/validate/` целиком, тест-инфраструктура пакета `core`
(её сегодня нет вообще), три стадии вызова — `validate`, `resolve_paths`, `build_argv`.

**Вне объёма:** запуск процесса и песочница (E3), сборка события аудита и его запись (E4/E6),
`lock_check` и загрузка манифеста (E1/E0), классификация риска и апрувы (E5).

**Вне объёма явно, чтобы не повисло между эпиками:** резолв `exec[0]` в абсолютный путь и
сверка с binary allowlist — атака A4. `07-contracts.md` называет это «делом демона», таблица
эпиков не относит ни к E2, ни к E3. Отдаётся **E4**; здесь это записано, чтобы A4 не оказалась
ничьей.

## Решения владельца (приняты 2026-08-27)

| # | Решение | Выбор |
|---|---|---|
| D1 | Где живёт карта матчеров | Двухфазно: `prepareRecipe` один раз на загрузке, дальше пер-вызов |
| D2 | Словарь отказов | Свой `DenialCode` внутри `core`; замороженные контракты не трогаем |
| D3 | Кто пишет события | E2 — чистые функции + свой `durationUs`; события собирает E4 |
| D4 | `type: path` и несуществующий файл | Требовать существования; `ENOENT` → отказ |
| D5 | Нормализация резолвнутого пути | Нормализовать в NFC |
| D6 | Что едет в `denyReason` | Значение параметра — никогда; только имя, тип и ограничение |
| D7 | Неизвестные ключи в `params` | Отказ |
| D8 | `exec[0]` и binary allowlist | Вне E2, отдаётся E4 |
| D9 | Тест-инфраструктура `core` | vitest + мета-тест раннера; один корневой barrel |

## Требования

### Форма и вход

**R1.** Код живёт в `packages/core/src/validate/`. В графе пакета нет ни `re2`, ни `ajv`,
ни `yaml`, ни импортов Electron (ADR-0001). Проверяется тестом по образцу `deps.test.ts`,
а не обещанием.

**R2.** Форма двухфазная. `prepareRecipe(recipeName, recipe, matchers, manifestDir)` выполняется
один раз после загрузки манифеста и возвращает либо `PreparedRecipe`, либо ошибку подготовки.
`validateCall(prepared, params)` выполняется на каждый вызов и не делает ничего, что можно было
сделать один раз, — три стадии E2 целиком лежат внутри оверхед-бюджета ≤50 мс p95.

**R3.** Скомпилированный матчер берётся из `ParseManifestResult.matchers` по ключу
`matcherKey(recipeName, paramName)`. `new RegExp` от `Param.pattern` не вызывается нигде —
это ровно тот регресс, ради предотвращения которого существует R29 из E0.

**R4.** Отсутствие матчера для параметра `type: string` — **ошибка подготовки**, а не
пер-вызовная развилка. Развилка «матчер не найден» на горячем пути возвращает тот самый выбор,
запасной путь в котором — `new RegExp`.

**R5.** E2 не принимает и не умеет принять argv, путь к бинарю, `cwd` или профиль песочницы:
вход — имя рецепта и словарь параметров (И5).

### Валидация параметров

**R6.** Ключ в `params`, которого нет в `recipe.params`, — отказ. Обход `params` идёт через
`Object.hasOwn` либо словарь с нулевым прототипом: схема запрещает `__proto__` в именах
**манифеста**, но не в ключах **запроса**.

**R7.** Отсутствующий обязательный параметр — отказ. Отсутствующий необязательный пропускается
и не даёт ни одного элемента argv.

**R8.** Тип значения проверяется до ограничений. `null`, массив, объект и значение чужого типа —
отказ до того, как дело дойдёт до `pattern`, `values` или границ.

**R9.** `string` — проходит `matcher.test`, затем `maxLength`, считаемый по кодовым точкам,
а не по единицам UTF-16.

**R10.** `enum` — значение строго из `values`, сравнение точное.

**R11.** `number` — конечное число (`1e400` из JSON даёт `Infinity`, это отказ), затем `min`,
`max`, `integer`.

**R12.** `boolean` — строго `true` или `false`; строка `"true"` не принимается.

### Резолв путей

**R13.** `type: path` резолвится через `realpath`, и **только потом** проверяется confinement
(И3). Проверка «строка не содержит `..`» защитой не является и не применяется как таковая.

**R14.** `root` резолвится через `realpath` тоже. Без этого сравнение ломается целиком:
на macOS `/var` — симлинк на `/private/var`, и нерезолвнутый `root` не совпадает с резолвнутым
путём ни для одного файла.

**R15.** Confinement проверяется через `path.relative`, а не через `startsWith(root)`.
Голый `startsWith` считает `/logs-evil/a` лежащим внутри `/logs`.

**R16.** Путь, которого нет, — отказ: `realpath` бросает `ENOENT`. Следствие записывается как
ограничение, а не как недоделка: `type: path` в текущей форме не выражает путь **для записи**.

**R17.** Резолвнутый путь нормализуется в NFC перед тем, как попасть в argv и в параметры,
по которым считается `argsHash`. Иначе один и тот же файл имеет два разных идентификатора
подтверждения, и апрув со `scope: recipe_and_args` в E5 не переживает смену формы записи.

**R18.** `cwd` рецепта резолвится на этой же стадии — по контракту события `cwd` впервые
появляется именно на `resolve_paths`.

### Сборка argv

**R19.** argv собирается в порядке объявления параметров в манифесте: порядок входит в
нормализованную форму рецепта именно потому, что из него собирается argv (ADR-0006).

**R20.** Значение параметра попадает в argv **отдельным элементом** массива. Слот `{}`
раскрывается не более одного раза на элемент. Конкатенации строки команды не происходит нигде —
инъекция убивается конструкцией, а не проверкой (И1, И2).

**R21.** `boolean` раскрывается присутствием или отсутствием своих элементов argv, без подстановки.

**R22.** Ни один параметр не попадает в `exec`, `cwd` или профиль песочницы. Загрузка это уже
гарантирует; E2 не полагается на неё молча, а имеет собственный тест на инвариант.

### Отказы и наблюдаемость

**R23.** E2 — чистые функции: ни часов, ни ввода-вывода, ни записи событий. Возвращается
размеченный результат и измеренная `durationUs` каждой стадии (`process.hrtime.bigint`).
Событие `AuditEvent` собирает E4. Обязанность «событие пишется на каждой стадии, включая
отказ» переходит к E4, и это записано здесь, чтобы не потеряться на шве.

**R24.** Отказ несёт стадию и типизированный `DenialCode` — юнион, объявленный в `core`.
Замороженная поверхность контрактов не расширяется: `stage` уже различает `validate` и
`resolve_paths`, а потребителю, которому нужна причина точнее, доступен импорт из `core`.

**R25.** Текст причины **никогда не содержит значение параметра** — только имя параметра, его
тип и само нарушенное ограничение (паттерн, список `values`, границы, `root`). Это не стиль:
`canonicalizeJcs` бросает на одиночном суррогате, `chainHash` канонизирует событие целиком,
поэтому эхо отравленного значения в причину даёт отказ, который **не будет записан** — а
контракт называет отказ без записи багом. Закрывается конструкцией, а не санитайзером.

**R26.** Дополнительно, поясом поверх подтяжек: любая строка, доезжающая до причины отказа,
проходит зачистку одиночных суррогатов. `sanitizeDescription` их не вырезает — проверено.

**R27.** Резолвнутый путь и граница confinement в причине отказа показываются (этого требует
сценарий S4). Они приходят из файловой системы, а не от вызывающего, и суррогата содержать
не могут.

### Корпус атак

**R28.** Тесты покрывают корпус из `09-metrics-and-eval.md`, а не отдельные примеры:
для A1 — `;`, `&&`, `$()`, обратные кавычки, перевод строки, юникод-омоглифы, нулевой байт;
для A2 — `../`, абсолютный путь, URL-кодирование, двойное кодирование; для A3 — симлинк на
файл и симлинк на каталог, через который идёт обход.

**R29.** Сценарии S3 и S4 воспроизводимы как тесты, а не только на демо: S3 останавливается
на `validate` с указанием паттерна, S4 — обоими вызовами на `resolve_paths`, и ни один из
четырёх не доходит до сборки argv.

### Инфраструктура

**R30.** У `packages/core` появляется работающий тест-раннер: `vitest.config.ts`,
`"test": "tsc -b && vitest run"`, и мета-тест по образцу `domain.test.ts`, падающий, если
тестовый файл положили мимо `include`. Сегодня `yarn test` пропускает пакет молча — ровно
то состояние, против которого написан R21 в E0.

**R31.** Экспорт — один корневой barrel `packages/core/src/index.ts`. Subpath-входы не
заводятся: они понадобятся, когда E3 принесёт node-only зависимости, и заводить их заранее
значит замораживать форму, которой ещё нет потребителя.

## Что E2 не делает и не обещает

| Ограничение | Формулировка |
|---|---|
| TOCTOU | Файл можно подменить между резолвом в E2 и открытием в E3. Проверено: резолвнутая строка — не стабильный дескриптор. Митигируется тем, что `denyRead` песочницы от резолва не зависит. E2 это **не закрывает** |
| Качество regex | `pattern` пишет автор манифеста. Слабый regex — слабая первая линия; спасает вторая |
| Путь для записи | `type: path` требует существующий файл (R16). Рецепт, которому нужен выходной путь, сегодня невыразим |
| Внутрь процесса | Валидатор не видит, что запущенный код делает. Сценарий S5 — про это, и E2 его не отменяет |
| Платформа | Резолв и confinement проверены на macOS arm64, node 22. Linux и Windows не проверялись |

## Чек-лист приватности

| Вопрос | Ответ |
|---|---|
| Собираем ли новые персональные данные | Нет |
| Что чувствительного проходит через E2 | Значения параметров и резолвнутые пути пользователя |
| Уходит ли что-то наружу | Нет. Чистые функции, ни сети, ни записи на диск |
| Логируются ли секреты | Нет. Значение параметра не попадает в причину отказа по R25 |
| Есть ли пути пользователя в артефактах | Резолвнутые пути и `cwd` — да, локально. В тестах — только временные каталоги |

## Критерий готовности

Все `R1..R31` реализованы; `yarn typecheck && yarn build && yarn test` зелёные на всём графе;
`yarn test` перестаёт молча пропускать `core`.

Исполняемые пункты — каждый проверяется командой, а не чтением:

- корпус A1 не проходит ни одним вектором, и ни один вызов не доходит до `build_argv`;
- симлинк на каталог, через который идёт обход, отвергается — лексическая проверка его пропускает;
- `/logs-evil` не считается лежащим внутри `/logs`;
- параметр с одиночным суррогатом даёт отказ, который **успешно канонизируется** и хэшируется;
- рецепт с `min: 10, max: 1` не грузится (закрыто правилом 10 в `refine`, коммит `693c8db`);
- граф пакета `core` не содержит `re2`, `ajv`, `yaml` и Electron.
