# E2 — валидатор параметров, резолв путей, сборка argv

**Ветка:** `v2/e2-validate` · **Трек:** full · **Источник истины:** `docs/06-epics.md` (строка E2),
`docs/07-contracts.md`, инварианты И1–И3 и И5 из `docs/02-architecture.md`, замороженная
поверхность `packages/contracts`.

## Цель

Первая линия обороны: превратить недоверенный `{recipeName, params}` в проверенный argv-массив,
резолвнутые пути и отказ с внятной причиной — так, чтобы строки команды не существовало ни на
одном шаге. Всё, что E2 отдаёт наружу, потребляет E3 (запуск) и E4 (шов).

## Границы

**В объёме:** `packages/core/src/validate/` целиком, тест-инфраструктура пакета `core`
(её сегодня нет вообще), три стадии вызова — `validate`, `resolve_paths`, `build_argv`.

**Вне объёма:** запуск процесса и песочница (E3), сборка события аудита и его запись (E4/E6),
`lock_check` и загрузка манифеста (E1/E0), классификация риска и апрувы (E5).

**Вне объёма явно, чтобы не повисло между эпиками:** резолв `exec[0]` в абсолютный путь и
сверка с binary allowlist — атака A4. `07-contracts.md` называет это «делом демона», таблица
эпиков не относит ни к E2, ни к E3. Отдаётся **E4**; здесь это записано, чтобы A4 не оказалась
ничьей.

## Решения владельца (приняты 2026-08-27)

| # | Решение | Выбор |
|---|---|---|
| D1 | Где живёт карта матчеров | Двухфазно: `prepareRecipe` один раз на загрузке, дальше пер-вызов |
| D2 | Словарь отказов | Свой `DenialCode` внутри `core`; замороженные контракты не трогаем |
| D3 | Кто пишет события | E2 — чистые функции + свой `durationUs`; события собирает E4 |
| D4 | `type: path` и несуществующий файл | Требовать существования; `ENOENT` → отказ |
| D5 | Нормализация резолвнутого пути | **Отменено ревью:** нормализации нет нигде — см. R17. Мотив даёт сам `realpath`, а NFC склеивал два разных файла в один апрув |
| D6 | Что едет в `denyReason` | На `validate` — никогда значение; на `resolve_paths` — резолвнутый путь, осознанное исключение |

| D8 | `exec[0]` и binary allowlist | Вне E2, отдаётся E4 |

## Требования

### Форма и вход

**R1.** Код живёт в `packages/core/src/validate/`. Граф пакета проверяется **белым списком**,
а не чёрным: множество достижимых голых специфаеров обязано быть подмножеством явно
разрешённых. Чёрный список здесь не работает — обход в `deps.test.ts` записывает голый
специфаер и внутрь пакета не заходит, поэтому правдоподобный регресс
`import … from '@mcpproxy/contracts/validate'` (тянущий `ajv`, `yaml`, `re2`) не попал бы ни
под одно запрещённое имя. Проверяются обе половины графа — `.js` и `.d.ts`.

**R2.** Форма двухфазная. `prepareRecipe(recipeName, recipe, matchers, manifestDir)` выполняется
один раз после загрузки манифеста и возвращает либо `PreparedRecipe`, либо ошибку подготовки.
`validateCall(prepared, params)` выполняется на каждый вызов и не делает ничего, что можно было
сделать один раз, — три стадии E2 целиком лежат внутри оверхед-бюджета ≤50 мс p95.

**R3.** Скомпилированный матчер берётся из `ParseManifestResult.matchers` по ключу
`matcherKey(recipeName, paramName)`. `new RegExp` от `Param.pattern` не вызывается нигде —
это ровно тот регресс, ради предотвращения которого существует R29 из E0.

**R4.** Отсутствие матчера для параметра `type: string` — **ошибка подготовки**, а не
пер-вызовная развилка. Развилка «матчер не найден» на горячем пути возвращает тот самый выбор,
запасной путь в котором — `new RegExp`.

**R5.** E2 не принимает и не умеет принять argv, путь к бинарю, `cwd` или профиль песочницы:
вход — имя рецепта и словарь параметров (И5).

### Валидация параметров

**R6.** Ключ в `params`, которого нет в `recipe.params`, — отказ. Обход `params` идёт через
`Object.hasOwn` либо словарь с нулевым прототипом: схема запрещает `__proto__` в именах
**манифеста**, но не в ключах **запроса**.

**R7.** Отсутствующий обязательный параметр — отказ. Отсутствующий необязательный пропускается
и не даёт ни одного элемента argv.

**R8.** Тип значения проверяется до ограничений. `null`, массив, объект и значение чужого типа —
отказ до того, как дело дойдёт до `pattern`, `values` или границ.

**R9.** `string` — проходит `matcher.test`, затем `maxLength`, считаемый по кодовым точкам,
а не по единицам UTF-16.

**R10.** `enum` — значение строго из `values`, сравнение точное.

**R11.** `number` — конечное число (`1e400` из JSON даёт `Infinity`, это отказ), затем `min`,
`max`, `integer`.

**R12.** `boolean` — строго `true` или `false`; строка `"true"` не принимается.

### Резолв путей

**R13.** `type: path` резолвится через `realpath`, и **только потом** проверяется confinement
(И3). Проверка «строка не содержит `..`» защитой не является и не применяется как таковая.

**R14.** `root` резолвится через `realpath` тоже. Без этого сравнение ломается целиком:
на macOS `/var` — симлинк на `/private/var`, и нерезолвнутый `root` не совпадает с резолвнутым
путём ни для одного файла.

**R15.** Confinement проверяется через `path.relative`, а не через `startsWith(root)`.
Голый `startsWith` считает `/logs-evil/a` лежащим внутри `/logs`.

**R15а.** Лексическая предпроверка **советующая, а не запрещающая**: она выбирает, каким
кодом назвать отказ, и никогда сама по себе не отвергает вызов.

Механика: кандидат прогоняется через предикат лексически; независимо от исхода вызывается
`realpath`; решение принимает только проверка после резолва (R13). Предпроверка влияет
ровно на одно — если она не прошла, любой последующий провал называется `path-escapes-root`,
а не `path-not-found`.

Запрещающей она быть не может, и это доказано замером в обе стороны. Против лексического
корня она отвергает законное значение в realpath-форме; против резолвнутого — законное
значение в той форме, в какой корень объявлен в манифесте. Общая формулировка хуже частной:
**любой** законный файл внутри `root`, достигнутый через симлинк, отвергается лексическим
предикатом, потому что лексический предикат симлинков не видит — ровно поэтому существует И3.

**Что именно она закрывает, и что нет.** Замерено, а не заявлено. Закрыта **лексическая**
спелляция обхода: `../../../etc/passwd` и `../../../etc/nope` дают один и тот же код. Эта
спелляция бесплатна для атакующего, поэтому её и стоило закрыть первой.

**Не закрыта** спелляция через симлинк, созданный внутри `root`: он лексически лежит внутри,
предпроверка проходит, и коды снова различаются — `path-escapes-root` для существующей цели,
`path-not-found` для несуществующей. Ирония точная: R15а обоснована тем, что лексический
предикат не видит симлинков, и слепое пятно, о котором эта фраза, — ровно то, через которое
остаток и достаётся.

Цена этой спелляции для атакующего выше: нужен примитив записи внутрь `root`, чтобы создать
симлинк, и по симлинку на каждую проверяемую цель. Это соответствует рамке проекта — не
«атака невозможна», а «атака дороже и оставляет след»: каждый созданный симлинк и каждый
отказ попадают в аудит.

Утверждение «бит о существовании произвольного пути наружу не уходит» **неверно** и здесь не
делается. Верное: уходит дороже и заметнее. Остаток записан в ограничениях. Это не замена проверки после `realpath` — И3 требует именно
её, и она остаётся, — а сужение утечки: без предпроверки коды отказа различают «путь вне
`root` и существует» и «пути нет», то есть отдают модели по одному биту о произвольном пути
на диске за вызов. С предпроверкой явный обход отвергается по границе, не по существованию,
и оракул схлопывается там, где его дешевле всего убрать.

Побочно предпроверка чинит тест: без неё вектор `../../.ssh/id_rsa` во временной фикстуре
падает по `ENOENT`, и тест зелен даже при полностью отсутствующем confinement.

**R16.** Путь, которого нет, — отказ: `realpath` бросает `ENOENT`. Следствие записывается как
ограничение, а не как недоделка: `type: path` в текущей форме не выражает путь **для записи**.

**R17.** Нормализация Unicode **не применяется нигде**. Идентичность вызова — это результат
`realpath` как есть: и в argv, и в параметрах, по которым считается `argsHash`.

Это разворот решения D5, и основание замерено. Мотив, ради которого нормализация вводилась,
`realpath` даёт сам: `{file: "./logs/a.log"}` и `{file: "/abs/logs/a.log"}` резолвятся в одну
строку и дают один `argsHash` **без всякой нормализации**. А NFC при этом склеивает в один
хэш два *разных* пути: на файловой системе с байтовыми именами NFC- и NFD-форма — разные
файлы, и апрув со `scope: recipe_and_args`, выданный на один, авторизовал бы вызов,
открывающий другой. Отказ в небезопасную сторону.

Обратная цена честная и мелкая: на macOS один файл, запрошенный в двух формах записи, даёт
два разных `argsHash`, то есть один лишний запрос подтверждения. Отказ в безопасную сторону.

Побочно это снимает конфликт с R16: строка, существование которой проверено, и строка,
уходящая в argv, — одна и та же по построению, а не по дисциплине.

**R18.** `cwd` рецепта имеет ровно одного вычислителя — подготовку рецепта, и вычисляется
один раз, а не на каждый вызов. По контракту события `cwd` впервые **появляется** на стадии
`resolve_paths`; это утверждение о том, где он виден, а не о том, кто его считает. Двух полей
с именем `cwd` и потенциально разным содержимым в результате не существует.

### Сборка argv

**R19.** argv собирается в порядке объявления параметров в манифесте: порядок входит в
нормализованную форму рецепта именно потому, что из него собирается argv (ADR-0006).

**R20.** Значение параметра попадает в argv **отдельным элементом** массива. Слот `{}`
раскрывается не более одного раза на элемент. Конкатенации строки команды не происходит нигде —
инъекция убивается конструкцией, а не проверкой (И1, И2).

**R20а.** Подстановка значения в слот **не интерпретирует подставляемое**. `String.replace`
со строковой заменой трактует `$&`, `` $` ``, `$'` и `$$` как управляющие последовательности,
и это не теоретическая придирка: замерено, что существующий файл с именем `a$'b.log`, прошедший
confinement, даёт argv с путём `ab.log` — другим и несуществующим. У `path`-параметра нет ни
`pattern`, ни `maxLength`, так что `$` в имени не фильтрует никто, а имена с `$` законны.

Последствия, если этого не сделать, шире порчи одного аргумента: argv перестаёт быть равен
строке, прошедшей проверку, — то есть падает R17 и R31, — а `argsHash` считается по одному
пути, тогда как процесс открывает другой. При `scope: recipe_and_args` человек подтверждает
один файл, а E3 читает другой.

**R21.** `boolean` раскрывается присутствием или отсутствием своих элементов argv, без подстановки.

**R22.** Ни один параметр не попадает в `exec`, `cwd` или профиль песочницы. Загрузка это уже
гарантирует; E2 не полагается на неё молча, а имеет собственный тест на инвариант.

### Отказы и наблюдаемость

**R23.** E2 — чистые функции: ни часов, ни ввода-вывода, ни записи событий. Возвращается
размеченный результат и измеренная `durationUs` каждой стадии (`process.hrtime.bigint`).
Событие `AuditEvent` собирает E4. Обязанность «событие пишется на каждой стадии, включая
отказ» переходит к E4, и это записано здесь, чтобы не потеряться на шве.

**R24.** Отказ несёт стадию и типизированный `DenialCode` — юнион, объявленный в `core`.
Замороженная поверхность контрактов не расширяется: `stage` уже различает `validate` и
`resolve_paths`, а потребителю, которому нужна причина точнее, доступен импорт из `core`.

**R25.** На стадии `validate` текст причины **никогда не содержит значение параметра** —
только имя, тип и нарушенное ограничение (паттерн, список `values`, границы, `root`).

**R26.** На стадии `resolve_paths` резолвнутый путь в причине показывается — этого требует
сценарий S4, где зал должен увидеть границу confinement. Это **осознанное исключение** из
R25, а не противоречие ему: для пути внутри `root` резолвнутая строка и есть значение
параметра, и спрятать её значит отнять у S4 предмет демонстрации.

**R27.** Любая строка, доезжающая до причины отказа, проходит **две** зачистки, и обе
обязательны, потому что каждая закрывает то, что пропускает другая: `sanitizeDescription`
из контрактов вырезает `Cc`/`Cf` и ANSI, но одиночные суррогаты (`Cs`) оставляет; собственная
зачистка вырезает суррогаты, но не `Cf`. Проверено обеими сторонами. Это не паранойя:
`realpath` возвращает имя файла дословно, включая bidi-override, а создать файл с таким
именем внутри разрешённого каталога модель угроз допускает — и эта строка уезжает в
Electron UI.

**R28.** **Ни одно значение не покидает E2, не пережив канонизацию.** Гейт стоит на трёх
источниках строк, и все три обязательны, потому что каждый минует предыдущий:

1. значения параметров вызова — до проверки паттерна, иначе вердикт зависит от того,
   насколько строг автор манифеста;
2. результат `realpath` — он **заменяет** проверенный вход новой строкой, собранной из имён
   на диске, то есть гейт над входом его не покрывает;
3. строки, пришедшие из самого рецепта: `exec`, `cwd`, `root`, шаблоны `argv`, значения
   `enum`, **имена параметров** и **имя рецепта**. Последние два — не педантизм: замерено,
   что `canonicalizeJcs` проверяет и ключи объекта, а не только значения, а имена параметров
   становятся ключами в `params`, по которым считается `argsHash`, и `recipeName` уезжает в
   него же первым аргументом. Загрузчик ограничивает их схемой, но `prepareRecipe` принимает
   `Recipe`, собранный программно и минующий загрузчик, — ровно тот довод, по которому
   существует R22.

Непригодное значение даёт **отказ** с собственным кодом, а не переписывается санитайзером.
Текст причины сюда не входит — он не значение, а сообщение, и им занимается R27.

Это не дублирование R27, а закрытие другой дыры — на **успешном** пути. Замерено: `^.{0,64}$`
— законный паттерн манифеста, RE2 его принимает, и на значении с одиночным суррогатом он
возвращает `true`. Дальше значение едет в argv, и `chainHash` с `argsHash` бросают
`TypeError`. То есть вызов **разрешён**, а событие записать нельзя — при том что контракт
называет отказ без записи багом, а для манифеста ровно этот класс уже закрыт проверкой
хэшируемости на загрузке. Для параметров вызова симметричной проверки нет нигде, кроме E2,
и слабый, но законный паттерн — принятое ограничение (`10-honest-limitations.md`), то есть
полагаться на автора манифеста здесь нельзя. Отказ, а не санитизация — прецедент задан
контрактом: отравленное значение `enum` тоже ошибка, а не тихая переписка.

**R29.** Контейнер `params` проверяется по форме до обращения к ключам: `Object.keys(null)`
бросает, и крэш на границе доверия — это отказ без следа в аудите. `IpcRequest.params` —
тип, а не рантайм-гарантия; по сокету приходит произвольный JSON.

**R30.** Длина любого строкового значения ограничена абсолютным потолком, независимым от
`maxLength` манифеста. `PathParam` не имеет ни `pattern`, ни `maxLength` вовсе, поэтому без
этого потолка путь в мегабайт доедет до `realpath`, argv, `argsHash` и записи аудита.
Прецедента в доках у этого потолка нет — родственный `JCS_MAX_DEPTH` ограничивает глубину
вложенности, а не длину, и это другой класс.

**R30а.** Ограничено и количество отказов, и длина имени параметра в отказе. `IpcRequest`
потолка размера не несёт, а полный контроль над сокетом входит в модель угроз (И6): запрос
со ста тысячами неизвестных ключей иначе даёт сто тысяч санитизированных отказов, которые E4
обязан сериализовать в append-only лог. Имена параметров манифеста ограничены схемой, ключи
запроса — нет.

**R31.** Успешный результат отдаёт наружу **проверенные параметры**, а не только argv:
`argsHash` считается по значениям после валидации и резолва — это записано в самом контракте.
Без них E4 посчитал бы хэш по сырым `params`, и тогда нормализация R17 бессмысленна, а
`{file: "./logs/a.log"}` и `{file: "/abs/logs/a.log"}` перестают быть одним вызовом.

### Корпус атак

**R32.** Тесты покрывают корпус из `09-metrics-and-eval.md`, а не отдельные примеры:
для A1 — `;`, `&&`, `$()`, обратные кавычки, перевод строки, юникод-омоглифы, нулевой байт;
для A2 — `../`, абсолютный путь, URL-кодирование, двойное кодирование; для A3 — симлинк на
файл и симлинк на каталог, через который идёт обход.

**R33.** Сценарии S3 и S4 воспроизводимы как тесты, а не только на демо: S3 останавливается
на `validate` с указанием паттерна, S4 — обоими вызовами на `resolve_paths`, и ни один из
четырёх не доходит до сборки argv.

### Инфраструктура

**R34.** У `packages/core` появляется работающий тест-раннер: `vitest.config.ts`,
`"test": "tsc -b && vitest run"`, и мета-тест по образцу `domain.test.ts`, падающий, если
тестовый файл положили мимо `include`. Сегодня `yarn test` пропускает пакет молча — ровно
то состояние, против которого написан R21 в E0.

**R35.** Экспорт — один корневой barrel `packages/core/src/index.ts`. Subpath-входы не
заводятся: они понадобятся, когда E3 принесёт node-only зависимости, и заводить их заранее
значит замораживать форму, которой ещё нет потребителя.

## Что E2 не делает и не обещает

| Ограничение | Формулировка |
|---|---|
| TOCTOU | Файл можно подменить между резолвом в E2 и открытием в E3. Проверено: резолвнутая строка — не стабильный дескриптор. Митигируется тем, что `denyRead` песочницы от резолва не зависит. E2 это **не закрывает** |
| Качество regex | `pattern` пишет автор манифеста. Слабый regex — слабая первая линия; спасает вторая |
| Путь для записи | `type: path` требует существующий файл (R16). Рецепт, которому нужен выходной путь, сегодня невыразим |
| Внутрь процесса | Валидатор не видит, что запущенный код делает. Сценарий S5 — про это, и E2 его не отменяет |
| Платформа | Резолв и confinement проверены на macOS arm64, node 22. Linux и Windows не проверялись |
| Confinement именной, не инодный | Жёсткая ссылка внутри `root` на файл снаружи проходит `realpath` и `relative` целиком: разрешается **имя**, а не инод. Модель угроз называет только симлинк (A3). Митигация та же, что у TOCTOU — `denyRead` песочницы |
| Оракул существования | Схлопнут только для **лексической** спелляции обхода (`../../etc/x`): там существующая и несуществующая цель дают один код. Симлинк, созданный внутри `root`, лексически лежит внутри, предпроверку проходит, и различие кодов возвращается — то есть один бит о произвольном пути на диске за вызов остаётся доступен ценой примитива записи в `root`. Замерено. Митигация та же, что у TOCTOU и жёстких ссылок: `denyRead` песочницы плюс след в аудите на каждый созданный симлинк |
| Текст отказа называет цель | При выходе за границу причина показывает **резолвнутый путь** — этого требует S4, где зал должен увидеть, куда вызов на самом деле указывал. Следствие: для целей под симлинком текст различает существующую и несуществующую цель даже там, где код одинаков. Это осознанная плата за наблюдаемость демонстрации, а не недосмотр |
| Оверхед не измерен | Бюджет ≤50 мс p95 — цель, а не замер. Три стадии E2 в него входят, но измерение делается в E8/E9, где есть с чем сравнивать: оверхед считается **относительно прямого вызова** того же скрипта |

## Чек-лист приватности

| Вопрос | Ответ |
|---|---|
| Собираем ли новые персональные данные | Нет |
| Что чувствительного проходит через E2 | Значения параметров и резолвнутые пути пользователя |
| Уходит ли что-то наружу | Нет. Чистые функции, ни сети, ни записи на диск |
| Логируются ли секреты | Нет. Значение параметра не попадает в причину отказа по R25 |
| Есть ли пути пользователя в артефактах | Резолвнутые пути и `cwd` — да, локально. В тестах — только временные каталоги |

## Критерий готовности

Все `R1..R35` (включая `R15а`) реализованы; `yarn typecheck && yarn build && yarn test`
зелёные на всём графе; `yarn test` перестаёт молча пропускать `core`.

Исполняемые пункты — каждый проверяется командой, а не чтением:

- корпус A1 не проходит ни одним вектором, и ни один вызов не доходит до `build_argv`;
- симлинк на каталог, через который идёт обход, отвергается — лексическая проверка его пропускает;
- `/logs-evil` не считается лежащим внутри `/logs`;
- параметр с одиночным суррогатом даёт отказ, который **успешно канонизируется** и хэшируется;
- он же не проходит **на успешном пути**: рецепт с законным паттерном `^.{0,64}$` отвергает
  такое значение, а не пропускает его в argv — иначе `chainHash` бросит на разрешённом вызове;
- `validateCall(prepared, null)` даёт отказ, а не `TypeError`;
- `argsHash(recipeName, result.params)` не бросает, совпадает для относительного и
  абсолютного написания одного файла (это даёт `realpath`, не нормализация) и **различается**
  для NFC- и NFD-пути, потому что это разные пути; строка в argv равна тому, что вернул
  `realpath`, байт в байт;
- законное значение в realpath-форме проходит confinement, а не отвергается предпроверкой —
  тест ставится в каталоге, корень которого лежит за симлинком, и это утверждается первым;
- запрос с большим числом неизвестных ключей даёт ограниченный список отказов, а не список
  длиной с запрос;
- граф `core` проверен белым списком, и `import … from '@mcpproxy/contracts/validate'`
  роняет тест;
- рецепт с `min: 10, max: 1` не грузится (закрыто правилом 10 в `refine`, коммит `693c8db`);
- граф пакета `core` не содержит `re2`, `ajv`, `yaml` и Electron.
