## 1. Что даёт `packages/contracts` (T1, читан исходник)

### Три входа с разными зависимостями — это архитектурная развилка E7

| Вход | Типы | Что тянет | Годен для рендерера |
|---|---|---|---|
| `@mcpproxy/contracts` | `dist/index.d.ts` | ничего | **да** |
| `@mcpproxy/contracts/validate` | — | `ajv`, `yaml`, `re2` (нативный) | нет |
| `@mcpproxy/contracts/audit` | — | `node:crypto` | **нет** |
| `@mcpproxy/contracts/schema` | сырой JSON Schema | — | да |

`ChainedEvent` намеренно лежит в корневом входе (`src/event.ts`), а `verifyChain` — за
`./audit`. Следствие: бейдж «цепочка верифицирована» (S9) **обязан** считаться в main-процессе
и ехать в рендерер результатом, иначе `node:crypto` попадает в бандл рендерера, который по И8
обязан быть `sandbox: true`.

### Транспорта событий в контракте нет

`IpcRequest` (`src/ipc.ts:70`) описывает только shim → демон. Канал «демон → Electron»
не объявлен нигде. E7 его изобретает, и он же станет швом для E4.

### 13 стадий

`src/domain.ts:12-25` (тип) и `:28-42` (рантайм-массив `stageOrder`):

```
received · lock_check · validate · resolve_paths · build_argv · classify_risk ·
approval · build_env · build_profile · spawn · violation · redact · complete
```

`violation` может повторяться (`domain.ts:27`) — таймлайн не список фиксированной длины.

Русские подписи стадий есть в `@mcpproxy/design` (`semantic.ts:48-62`), порядок — в
`contracts`. `README.md:73` дизайн-системы обещает `stageOrder` из `@mcpproxy/design` —
**это неверно**, там его нет.

### Таблица «стадия → какие поля впервые появляются»

Приземлилась комментарием в `src/event.ts:23-36`, не экспортируемой константой (решение
зафиксировано в `handoff-notes.md:43-45` E0). В ней **12 строк на 13 стадий**: `validate`
не вводит ни одного нового поля.

|---|---|

| `lock_check` | `recipe.hash` |
| `resolve_paths` | `cwd` |

| `approval` | `approval` |

### Правила, которые сломают фикстуры, если их не знать

1. **Отсутствующее опциональное поле — отсутствующий ключ, не `null`.** `null` = «известно и
   пусто» (`exit.signal`, `denyReason` при `allowed`). Репозиторий компилируется с
   `exactOptionalPropertyTypes: true`, так что `argv: undefined` тоже не пройдёт.
   Вызов, стоящий на `lock_check`, обязан не иметь ключа `argv` вовсе — иначе UI отрисует
   выдуманный `argv: []` настоящей пустой командой (`docs/07-contracts.md:303-306`).
2. **Дайджесты — голый нижний регистр, ровно 64 hex, без префикса `sha256:`.** Префикс в
   `docs/07-contracts.md` — приём отображения (`audit/chain.ts:14-20`).
3. **Брендированные идентификаторы.** `RecipeName` / `SessionId` / `RequestId` строятся через
   `asRecipeName()` / `asSessionId()` / `asRequestId()`, иначе не компилируется.
4. **`durationUs` — длительность стадии**, не накопленная. `duration.overheadMs` только на
   `complete`, считается по стадиям вне `{spawn, violation, approval, complete}`.
5. **`protocolVersion` — версия сессии**, не константа сборки. Хотя бы одна фикстура должна
   нести старую ревизию, чтобы UI её не захардкодил.
6. **`schema: 'mcpproxy.audit/1'` читается терпимо** (`event.ts:49-51`): незнакомое значение
   рисуется как «форма новее меня», а не бросает.

### Формы, которые рисует UI

```ts
SandboxViolation { type: ViolationType; target: string; action: 'denied'|'allowed'; bytes: number }
ViolationType = 'network'|'file-read'|'file-write'|'mandatory-deny'|'process'
```

У нарушения **нет** ни времени, ни pid, ни идентификатора правила — всё остальное панель
берёт с объемлющего события. `action: 'allowed'` существует для observe-режима: панель не
имеет права считать, что всякое нарушение было заблокировано.

```ts
ChainVerification = { ok: true } | { ok: false; brokenAt: number }
```

Дискриминированный намеренно (`audit/chain.ts:47-56`): при `number | null` подделка **первой**
записи дала бы `brokenAt: 0`, ложное по `if`. Ветвиться по `ok`, не по истинности.

```ts
ApprovalRequest  { requestId, sessionId, recipeName, argsHash, tier, argv, cwd, profile }
ApprovalVerdict  { requestId, sessionId, channel, decision, scope, expiresAt }
ApprovalRecord   { channel, decision, scope, expiresAt, argsHash, sessionId }
ApprovalScope    = 'once' | 'until' | 'recipe_and_args'
ApprovalDecision = 'approved' | 'denied'
```

`ApprovalRequest` не несёт ни описания рецепта, ни значений параметров, ни `createdAt`.
Описание модалка джойнит сама по `recipeName`; обратный отсчёт — состояние, локальное для E7.
Истечение и отмена выражаются **отсутствием** вердикта, а не третьим значением решения.

```ts
LockDiff   { defaults: {was,is}|null, added[], removed[], changed[{name,was,is}] }
LockStatus = 'verified' | 'drifted' | 'absent'
```

Четыре слота дифф получил, чтобы одна правка `defaults` не размножалась по всем рецептам в
модалке (ADR-0006). **Дрейф lock — не риск-тир**: `high` ведёт к апруву, дрейф — к жёсткому
стопу с диффом. Два разных экрана, схлопывать нельзя.

### Четыре рецепта-заглушки

| Рецепт | Тир | Аннотации | Заметка |
|---|---|---|---|
| `run_tests` | medium | readOnly f, destructive f, idempotent t, openWorld f | `pattern` даёт **два** элемента argv |
| `build_project` | medium | те же | enum `debug\|release` |
| `analyze_logs` | low | только `readOnlyHint: true` | `path` с `root: ./logs` |
| `publish_release` | **high** | readOnly f, destructive t, idempotent f, openWorld t | единственный high; сеть на npm+github |

Тиры закреплены тестом `recipes.test.ts:49-64`, включая утверждение, что `publish_release` —
единственный `high`. Фикстуры инбокса апрувов должны быть на нём.

## 2. Дизайн-система `packages/design` (T1)

### Что уже есть

- **Токены**: полная тема (`bg`/`text`/`border`/`brand`/`state`) в светлом и тёмном, шкалы
  палитры, типографика, отступы, радиусы, тени, моушен, `zIndex` с отдельным слоем

поставляемом CSS **нет вообще**. Прототип таймлайна существует только внутри

`--shadow-modal` и `--z-approval` объявлены и не имеют ни одного потребителя.

### Баг, подтверждённый мной лично (T1)

`src/css/base.css:109` — `.btn-danger { background: var(--brand-base) }`. Генератор
(`scripts/generate-css.mjs:29`) схлопывает ключ `base` в имя группы, поэтому объявлена
`--brand`, а `--brand-base` не существует. Фон не резолвится; текст при этом
`--text-on-brand: #FFFFFF`. Ховер `:116` берёт `--brand-hover` и работает, поэтому баг виден
только в покое. `preview.html:611` использует `var(--brand)` правильно — расхождение между
поставляемым CSS и превью.

`.btn-danger` — кнопка подтверждения `publish_release` в S8, то есть баг внутри радиуса
поражения E7.

### Расхождения в документации (T1)

- `README.md:47` — заголовок «Четыре роли, а не три», таблица под ним перечисляет **пять**.
  `preview.html:726` исправлено на «Пять ролей».

  пропущены `approval` и `violation`. Каноничны `contracts`, не проза.

### Правила, которые связывают руки (цитаты)

- «Красный — семантика, а не украшение… появляется ровно в трёх местах: знак продукта,
  кольцо фокуса, критические состояния».
- Пять ролей: `ok` зелёный (штатно) · `warn` **янтарный — отбито, защита сработала** ·
  `danger` красный — **плохо по-настоящему** · `info` синий (ждём человека) ·
  `human` фиолетовый (решение человека действует).
- Исключение: `mandatory-deny` красный, хотя попытка отбита — «сам факт попытки записи в
  `.git/hooks` означает, что код пытался закрепиться. Это не рутина».
- «Цвет никогда не единственный носитель смысла» — рядом всегда текст или символ.
- «Моноширинный для argv, путей и хэшей… перенос по словам в argv запрещён».
- «Кольцо фокуса не убирается».
- «`sandbox: none` красится опасным всегда», плюс баннер во всю ширину.
- Тёмная тема основная, светлая равноправна и проектируется второй.

Дополнительно: помечать в UI рецепты с `*` в домене как «ослабленный режим»
(ADR-0007:45-46), и то же для `allowUnixSockets` / `enableWeakerNetworkIsolation` /
`allowAppleEvents` (`10-honest-limitations.md:97`).

### И8 целиком (`02-architecture.md:98-102`)

> `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, жёсткий CSP.
> **Каждое сообщение из renderer валидируется как недоверенный HTTP-запрос.**
> Инструменту безопасности провалиться здесь — значит провалить всё.

`preload` в И8 не назван — он следует из `contextIsolation` + `nodeIntegration: false`.

`packages/core` — «без единого импорта Electron» (`02-architecture.md:31`, ADR-0001:19).
E7 зависит только от `contracts` и `design`, как уже объявлено в его `package.json`.

E5 (апрувы) зависит от **E4 и E7**: окно — поверхность E7, брокер — E5.

## 4. Prior art (T3/T4, ~250 обращений к сети)

Полные ссылки — в отчёте агента; здесь то, что меняет решения. Числа из академических работ
я **не перепроверял** и помечаю как T3/T4: они пригодны как аргумент, не как истина.

### Таймлайн

- **Негативный результат, и он важен**: у цепочек фильтров Envoy и admission-контроллеров
  Kubernetes — ближайший инфраструктурный аналог 13 стадий — визуализации нет вообще.
  Скопировать ответ неоткуда; если экран сработает, он различающий, а не производный.
- **Chrome DevTools Network** — самый близкий механизм: строка несёт свёрнутую двухцветную
  полосу, полная разбивка по фазам живёт в отдельной вкладке. **Не случившиеся фазы просто
  отсутствуют, а не рисуются нулевыми полосками.** Прямо ложится на правило «нет ключа».
- **GitLab mini graph** — свёрнутый кластер всегда показывает результат **худшего** члена.
- **Jaeger UI PR #18** — красная иконка на спане с ошибкой, **фон строки при этом убрали**,
  иконка всплывает на свёрнутого родителя.
- **Little Snitch Connection Inspector** — поля деталей кликабельны и работают фильтрами по
  списку; отдельные счётчики «последний разрешён» / «последний отказан».
- **mitmproxy** — метка потока это строка-глиф, а не булево, плюс отдельный комментарий.
- **Blue Ocean и GitHub Actions независимо сошлись** на автораскрытии упавшего шага.
- **Избегать**: граф из узлов и рёбер (цепочка не ветвится); Buildkite рисует убитые задачи
  пустыми строками — для прокси убитый вызов самая важная строка, а не самая пустая.

### Апрувы

- Bravo-Lillo, SOUPS 2013 (T3): «ингибирующие аттракторы» дают детекцию подмены критического
  поля **44–74 % против 5–9 % контроля** и устойчивы к привыканию; победитель — **перепечатать
  критическое поле, вставка отключена**. Установившаяся цена ~3–5 с.
- Akhawe & Felt, USENIX 2013 (T3): «показать детали» кликают 1.6 % в Chrome и 0 % в Firefox.
  **Следствие: полный argv в основном тексте, а не за раскрытием.**
- Anthropic про Claude Code (T3): **93 % запросов разрешения одобряются**. Это не настроенный
  промпт, это переставший работать промпт — инбокс не должен быть той же поверхностью.
- GitHub и AWS требуют напечатать **имя конкретного объекта**, а не слово «DELETE». Аналог
  здесь — напечатать опасный токен **из самого argv**: путь, хост, `--force`. Один механизм
  закрывает и внимание, и привязку к конкретному запросу.
- Little Snitch держит **TTL и скоуп ортогональными выпадающими списками**, не слитыми
  кнопками, и называет цепочку процессов целиком.
- GitHub OAuth позволяет **сузить** запрошенное прямо на экране согласия.
- Избегать: лишние клики как заслон, и длинную прозу — оба измеримо не работают.

### «Защита сработала» против «плохо по-настоящему»

- **Microsoft Defender уже отгрузил ровно наше правило**: серьёзность и статус обнаружения —
  **два ортогональных поля**. Цвет — функция серьёзности, слово — функция диспозиции.
  Предотвращённая без ущерба угроза у них категоризуется как *Informational*, то есть Defender
  идёт **дальше** нас: не янтарь, а серый.
- CrowdStrike и Cortex XDR: два глагола, никогда третьего — `Prevention` / `Detection`.
  Строку вести словом диспозиции, чтобы оно пережило усечение.
- Анти-паттерн с именем: pfSense логирует все дропы красным — **100 % красного означает, что
  фаервол отработал идеально**, то есть красный не несёт информации.
- Chrome отказался красить HTTP красным **только потому, что это было слишком часто**, и ждал
  годы, пока доля упадёт. Сильнейшая цитата в пользу «янтарь ≠ красный».
- Felt et al. 2015 (T3): смена **текста** предупреждения даёт +1.2 пункта, смена **вида** —
  +26. И отдельно: жёлтый и оранжевый при достаточной яркости **не добирают контраста** ни с
  белым, ни с чёрным текстом — они шипнули серое поле с красным акцентом.
  **Следствие: янтарь как рамка/левая линейка/иконка, не как заливка под текстом.**
- WCAG 1.4.1 делает это вопросом соответствия: янтарь и красный — ровно та пара, которую
  путают протанопы и дейтеранопы, а это наше самое важное различие.
- Структурная защита от инфляции серьёзности: **сделать красный закрытым перечислением в
  коде**, а не параметром, который любая новая проверка может передать.

### Policy viewer

- **Дефолты аннотаций MCP — ловушка**: незаданное по спеке значит `destructiveHint: true` и
  `openWorldHint: true`, и спека требует считать аннотации недоверенными. Рисовать «не задано»
  нейтральным серым — фактическая ошибка. Нужны **два регистра: заявлено сервером против
  проверено прокси**.
- Chrome extension permissions: таблица «ключ манифеста → одно предложение по-человечески»,
  ~80 разрешений на ~30 строк. **Сжатие и есть продукт.** Плюс поглощение: предупреждение не
  показывается, если запрошено более широкое.
- AWS access levels: каждое действие ровно в одну корзину, плюс квалификатор покрытия
  «Full: Read · Limited: Write» вместо N бейджей.
- rakkess `--diff-with`: показывать **только дельту** от политики по умолчанию.
- Потолок: NN/g — больше двух уровней раскрытия обычно ломает юзабилити. Манифест → рецепт;
  сырой JSON это переключатель режима, а не третий уровень.

### Бейдж целостности

- Git `%G?` — **восемь** состояний, и «подпись верна» отдельно от «ключ доверен». Git
  отказывается схлопывать проверку в pass/fail. Состояние `E` (проверить невозможно) — то
  место, где почти все инструменты жульничают, откатываясь в зелёный.
- npm: «Built and signed on GitHub Actions» — **называет механизм, а не выносит вердикт**,
  и прямо оговаривает, что это не гарантия отсутствия вредоносного кода.

## 7. Electron — безопасность IPC и CSP (T1/T3, часть выводов проверена эмпирически)

Раздел собран из блока исправлений разведчика; исходный отчёт по тулчейну запрошен отдельно.
Всё ниже — то, что он **перепроверил и исправил у самого себя**, то есть наиболее надёжная
часть его работы.

### `file://` не даёт origin, по которому можно проверять отправителя

Совет «сравнивай `frame.origin`, а не `frame.url`» верен для http(s) и кастомных схем и
**опасен под `file://`**. По URL Standard §4.7 всякий `file:`-URL получает непрозрачный
origin, сериализуемый строкой `"null"`. Проверено запуском:

```
file:///Users/x/app/index.html            → origin "null", host ""
file://evil.example.com/Users/x/app/...   → origin "null", host "evil.example.com"
```

Пути совпадают, origin совпадает. То есть в упакованной сборке на `loadFile()` сравнение
origin сводится к `"null" === "null"` и не проверяет ничего, а подставленный в позицию
authority удалённый хост проходит.

**Следствие: кастомная схема `app://` перестаёт быть удобством и становится несущей** — она
возвращает проверку отправителя к одному точному сравнению в обоих режимах.

```js
protocol.registerSchemesAsPrivileged([{
  scheme: 'app',
  privileges: { standard: true, secure: true, supportFetchAPI: true, corsEnabled: true }
}]);
```

`corsEnabled: true` здесь обязателен: `supportFetchAPI` без него — это
**CVE-2026-70604 (High, CVSS 7.4)**, схема не подпадала под контроль CORS. Починено в
39.8.10 / 40.9.3 / 41.4.0 / 42.0.0.

`standard: true` даёт не только origin: **без него отключены localStorage, sessionStorage,
IndexedDB и cookies**, а разрешение относительных URL ведёт себя как у `file:`, что ломает
ссылки `/assets/…` из сборки Vite.

### `senderFrame` обнуляется собственным `await`

`senderFrame` — ленивый геттер, заново резолвящий фрейм в момент обращения. Асинхронная
обёртка-валидатор — ровно то, что его ломает. Типы менялись так:

```
electron@33.0.0  readonly senderFrame: WebFrameMain
electron@33.1.0  readonly senderFrame: WebFrameMain | null   ← PR #43473
```

```js
ipcMain.on('e', (event) => { event.senderFrame })                 // ок
ipcMain.on('e', async (event) => { await p; event.senderFrame })  // null
```

**Правило: `const frame = event.senderFrame` — первый оператор, до любого `await`**, затем
проверка `frame.detached` и `frame.parent !== null`.

### Валидация IPC — схемой, а не типами

**CVE-2026-70610 (Moderate, 5.4)**: копирование объектов через `contextBridge` учитывало
сеттеры прототипа, поэтому объекты из недоверенного содержимого могли нести
подконтрольный атакующему прототип — **несмотря на включённую contextIsolation**.
Обход из адвайзори: проверять `Object.hasOwn` либо копировать на объект с нулевым прототипом.

`.d.ts`-контракт стирается в рантайме и не останавливает ничего. Нужен разбор схемой на
границе. **Не через `@mcpproxy/contracts/validate`** — этот вход тянет нативный `re2`
в main-процесс; для границы IPC нужен отдельный маленький валидатор.

### Ошибки через IPC теряют всё, кроме `message`

Документация `ipcMain.handle`: наружу отдаётся **только свойство `message`** исходной ошибки,
а `contextBridge` вдобавок срезает пользовательские поля `Error`. То есть
`class DeniedError extends Error { code }` приезжает голым `Error`.

**Следствие: возвращать конверты, а не бросать.**
`type Result<T> = { ok: true; value: T } | { ok: false; error: SerializedError }`.

### CSP: заголовок и `<meta>` пересекаются, а не перекрывают

CSP3 §3.3 и MDN: политика из `meta` применяется **вместе** с остальными, и добавление
политики может только **ужесточить**. Практическое следствие: забытый `<meta>` в
`index.html` при живом заголовке молча затягивает политику, и ловить будешь фантом.
Отгружать ровно один механизм доставки.

Отдельно: `base-uri`, `form-action` и `frame-ancestors` **не наследуются от `default-src`** —
`default-src 'none'` всё ещё позволяет встроить страницу кому угодно.

`'unsafe-eval'` для React + Vite + TS не нужен; предупреждение Electron про небезопасный CSP
завязано ровно на разрешение eval.

Ветвиться на строгую и мягкую политику по **`NODE_ENV`, а не по `app.isPackaged`**: e2e гоняет
собранное приложение с `isPackaged === false` и иначе получил бы мягкую политику в
единственной автоматической проверке, которая вообще запускает настоящий рендерер.

Nonce достижим и в упакованном виде: рантайм Vite читает nonce из
`<meta property="csp-nonce">`, и его значение можно переписывать на каждый ответ внутри
`protocol.handle`. Это единственная конфигурация, дающая строгий `script-src` **без
`unsafe-inline` ни в dev, ни в prod**.

### Инструменты

  что проверяет факт наличия защиты, а не её корректность.
- **Значит, обеспечение структурное, а не линтерное**: одна обёртка на каждый привилегированный

- `@electron-toolkit/typed-ipc` — форма контракта хорошая, но рендерная половина требует

- `electron-trpc` — несовместим с `sandbox: true` без сборки preload (issue #116 открыт с

  отправителя.

### Аргумент, который стоит забрать в питч

**CVE-2022-29247 / GHSA-mq8j-3h7h-p8g7**: скомпрометированные дочерние рендереры могли
получить доступ к IPC без `nodeIntegrationInSubFrames`. Формулировка Electron: «если
приложение в песочнице, `nodeIntegrationInSubFrames` даёт доступ к API песочничного
рендерера, включая `ipcRenderer`… убедитесь, что все обработчики IPC проверяют `senderFrame`».

То есть сам Electron утверждает: проверка отправителя — слой, переживающий компрометацию
рендерера **даже при включённой песочнице**. Для продукта про безопасность это готовый
аргумент, почему И8 сформулирован именно так.

### Спор внутри разведки, разрешённый в пользу песочницы

Дочерняя ветка исследования вывела «ESM-preload вынуждает `sandbox: false`». Разведчик это
**отверг**: держать main в ESM, а **preload собирать в CJS** через
`rollupOptions.output.format: 'cjs'` — Vite отдаёт `.cjs`, Electron грузит его обычным
песочничным preload, потому что preload игнорирует поле `"type": "module"`.
`sandbox: true` сохраняется. Для этого продукта песочница и есть питч, менять её нельзя.

### Тулчейн — рекомендация разведки

**`electron-vite@5` + `electron-builder@^26.15.6`, Vite закреплён на `7.3.6`, Electron 43 или 44.**

Отпали: **Forge** — его плагин Vite официально экспериментальный и в исходнике жёстко задаёт
`formats: ['cjs']`, то есть ESM в main невозможен; **ручной tsc** — бандлер всё равно нужен
для preload и рендерера, а несобранный main это худший режим отказа в монорепо.

**Решение с наибольшим рычагом: собирать `@mcpproxy/contracts` и `@mcpproxy/design` внутрь
main/preload, а не выносить во внешние.** Это целиком убирает класс багов
«electron-builder + yarn workspaces» (eb#9945, eb#10033, forge#3734), потому что упаковщик
никогда не идёт по симлинку `workspace:*`.

### Три вещи, которые сломают первый запуск

1. **Electron 42+ больше не скачивает бинарь на установке.** Проверено по реестру: у
   `electron@41` был `postinstall`, у 42 и 44 секции `scripts` нет вообще, зато появился
   бин `install-electron`. electron-vite бросает `Error('Electron uninstall')`, issue #904
   открыт. Ударит и по CI на свежем клоне.
2. **electron-vite молча целится в `node16.17` / `chrome108`** — его таблица версий кончается
   на Electron 39, а промах отдаёт последнюю запись. Проверено в опубликованном тарболе
   5.0.0. Задавать `build.target` явно.
3. **preload выходит `.mjs` и не грузится под песочницей.** Принудительный `format: 'cjs'`.

- `packages/contracts/src/ipc.ts` уже экспортирует `IpcRequest` для границы **shim↔демон**.
